## 0. 三分钟速览

- 项目：ClawPi 智能小车电脑端控制台（Python + Tk）。电脑不装 ROS，通过 **rosbridge 9090 / web_video_server 8080 / SSH** 连车。
- 入口：`app/run.bat`（Windows）或 `bash app/run.sh`。依赖见 `app/requirements.txt`。
- 当前 7 个页面：**夹取、遥控、AI 助手、自动巡航、沙盘建模、沙盘导航、集成终端**（注册表 `app/carapp/features/__init__.py`）。
- 测试：`cd app && python -m unittest discover -s tests`，现有 **792** 个用例；本机单进程跑会在 Tk 析构处崩（见 §8），日常请用分模块方式。
- 这一轮主要做了：颜色追踪夹取的定位与夹取修复、逐车标定与车辆身份核对、全页面统一速度控件、沙盘导航从"能规划"到"能实车跑一段"的整链修复、**独立路网标注器**。
- 已知最大短板：**雷达地图在窄道/模型区有噪点**，沙盘外圈 25 cm 窄道过不去；AMCL 定位偶有 5~10 cm 偏差。这是接下来最值得投入的方向（§9）。

## 4. 技术路线

### 4.1 通信与实时数据
- ROS 侧：`rosbridge_websocket`（9090）订阅/发布；`web_video_server`（8080）拉 MJPEG 画面；SSH（paramiko）做导航服务、建图、终端。
- `/scan_raw` 走 `core/realtime_ros.py` 的 `RealtimeRosDelivery`：在 ROS 接收线程更新最新数据，**不进 Tk 队列**；页面通过 `Feature.realtime_ros_handlers()` 注册纯数据回调。切车/断线/退出用 `reset_realtime_ros()` 清空。
- 页面刷新：只有当前页跑 `on_tick()`（绘制/视频/控件），所有页都跑 `on_background_tick()`（会话收尾、许可检查、共享状态）。
- 底盘/舵机统一走 `AppContext.publish_twist()` / `publish_servo()` / `stop_base()`，带限位、红绿灯守卫与运动占用检查。

### 4.2 建图（沙盘建模）
1. 车端起厂家 SLAM Toolbox（`sync_slam_toolbox_node`，`scan:=/scan_raw`，参数文件 `/home/ubuntu/ros2_ws/src/slam/config/slam.yaml`，容器 ClawPi 内）。
2. 遥控低速跑一圈（建议直行 0.05 m/s、转弯点按、回起点闭环）。
3. 保存：`map_saver_cli` + `/slam_toolbox/serialize_map`，产出 `map.pgm/map.yaml/map.posegraph/map.data`，落在 `app/savedMap/<名字>/`，写 `manifest.json`（含 sha256）。
- 也试过 Cartographer（参数：`max_range 12`、`hit 0.70/miss 0.50`、`motion_filter .10 rad/.03 m`），但噪点更多，现以 SLAM Toolbox 为准。
- 地图分辨率 0.05 m/px；空旷处把噪声（树/灯柱）当障碍是常态，导航前要配 keepout 与路网。

### 4.3 定位与执行（沙盘导航）
1. 导入沙盘工程 `sandbox.json` → 上传 `map.pgm/yaml/keepout` 到车端容器 `/tmp/carapp_nav_<会话>/`，起 Nav2（AMCL + map_server + controller/planner/bt）。
2. 标定当前位置/朝向（AMCL 未激活时现在会排队、激活后自动提交，不会取消整轮）。
3. 选目标 → 电脑端规划 → `follow_path` 把整条路径发给车端。
4. 车端 `sandbox_runtime._check_road()`：校验起点位置/朝向（容忍 1.4 rad）→ 实时全局代价图按 `swept_clear(points, footprint, pass_cost)` 复核 → 通过后交给 Nav2 **FollowPath / RPP** 执行。
5. 失败处理：`blocked` 时封闭对应路段并尝试备用路（≤2 次）；取消/心跳/许可失效都会停车并记原因。

### 4.4 路网与工程格式
- `sandbox.json`：版本、帧、`calibration{source,target,transform}`、`edge_widths`、`narrow_nodes`、`keepout`、七文件 sha256。加载时强校验，改文件后必须重算哈希（`core/sandbox_project.py` 的 `save_network()` 已封装）。
- 路网：`road_network.yaml`，节点 `id/pose/name/to`；边宽 `edge_widths['a:b']`；`plan_route` 要求边宽 ≥ 0.23 m，并对 keepout 与定位图做整车扫掠。
- 规划：`core/road_network.py`（Dijkstra）+ `core/sandbox_route.py`（投影起点、双图扫掠、`rounded_path` 转角圆弧）。
- **当前导航功能（沙盘导航页）使用的路网是 pp/savedMap/sandbox_track_20261102/ 里的文件**：
oad_network.yaml + sandbox.json（map/roads/keepout 来自同一雷达图），按实车示教轨迹拟合、节点沿真实可走路径分布；导入时选该目录的 sandbox.json。
- 另一套可选网络：pp/savedMap/sandbox_nav_ready_20261101/（110 节点九宫格式，早期版本，规划成功率也不错、拐角贴合稍差）。

### 4.5 车体尺寸与安全阈值
- 车体默认 **0.30 × 0.18 m**（`navigation.sandbox_footprint = {front .19, rear .09, half .08}`，含夹爪余量；实车由用户确认）。
- `navigation.sandbox_pass_cost`：`253` = 机身避开内切膨胀（保守）；`254` = 允许贴边（零余量）。当前设 **254**。
- `navigation.sandbox_verify_path`：规划阶段是否做"整条路径整车扫掠"预检，当前 **false**（细节见 §7）；真正的硬校验仍在车端实时代价图。
- 车端还有：控制租约（心跳 2 s 断则作废）、起点朝向校验、`stop_all` 抢占。

### 4.6 夹取链路
- `features/gripper.py` 编排 + `features/tracking_pick.py` 页面状态 + `core/visual_pick.py` 策略/执行器 + `core/color_tracker.py` 识别。
- 标定键：**按车辆档案+颜色**（`HW-十位:红色`），旧的 `档案:地址:颜色` 键会自动迁移；换网线/Wi-Fi 不会丢标定。
- 关键规则：到夹取线才合爪（`arrive_margin=0`）、最后 12% 画面高度只直行、横向残差 >0.02 先对正再合、标定不可用时页面直接写原因。

### 4.7 速度与身份
- 全页面统一 `ui/speedpicker.py`（输入框 + 预设按钮 + 保存回调）：遥控、夹取、巡航、导航、建图都能直接改速度；建图页速度存 `mapping.speed`。
- 车辆身份：连上后后台 SSH 读 `/proc/device-tree/serial-number`，映射成 `HW-XXXXXXXX` 并与所选档案比对，不符会在日志与状态栏警告（`core/vehicle_identity.py`）。

## 7. 已修的几处"看起来像玄学"的问题（接手需要知道）

1. **夹取在离夹取线还差 2 cm 就合爪**：`arrive_margin` 早先允许提前停；现在必须到线，且末段只直行、横向残差收敛后才合。
2. **换连法就丢标定 / 夹取页按钮无反应**：标定改为按车辆身份存；`NameError: validate_calibration` 是改 import 时的漏项，已补回归测试；界面异常现在会写 `stderr` 与日志文件（`CARAPP_LOG_FILE` 环境变量）。
3. **导航"点开始没反应"**：按钮灰时页面下方黄字会列出缺失项（未连接、未启动定位、位姿未就绪、画面/录像/雷达未就绪、底盘被占用等），按提示补齐即可。
4. **点目标秒报没有路径**：多半是 APP 没重启、还在用旧的车体尺寸/边宽阈值。改完代码或配置务必重启。
5. **车走一半停路中间**：早先"客户端取消"没写原因；现在日志会区分"用户停止 / 控制许可被抢占 / 心跳中断 / 车端 abort"。`Failed to make progress` 则看局部代价图——keepout 滤镜已只挂全局图，局部膨胀降到 0.15。
6. **走路画龙**：RPP `lookahead .18`、`rotate_to_heading_min_angle .15`、角加速度 .9；同时规划出的路径在拐角做了二次贝塞尔圆弧（`rounded_path`），车不用在直角处停下来原地转。

## 9. 已知问题与建议（按优先级）

**P0 - 实车导航受地图质量限制**
雷达图在模型区/树/灯柱附近有碎噪，keepout 后走廊常在 25–30 cm；车身 30×18 cm 只剩几厘米余量，AMCL 5 cm 级偏差就可能被车端拒绝或中途 abort。建议：
- 用更慢速度多圈重录 + 手工把噪点区域并入 keepout（或标注为不可通行）；
- 或换更高分辨率/更好雷达参数后重新建图；
- 或先把导航限定在已确认够宽的主环（当前 110 节点工程的中间走廊）。

**P1 - 路网与现场对齐**
示教轨迹生成的路网（`sandbox_track_20261102`）已尽量贴真实路径，但拐角处仍可能擦边。用新做的 **路网标注器**逐点修最省事：`app/road_editor.bat` 打开工程 → 点节点/连线 → 保存（会重算 sha256）。

**P2 - 其它**
- 公开仓库仍跟踪 `小车账号密码信息.txt`（含 SSH 账号密码），**建议立刻改车密码并从仓库移除**；
- `app/config/settings.json` 里夹存了同学机器的绝对路径（`tracking_pick.calibrations` 的 `reference_image`），不影响功能，可清；
- `.work/` 下的建图/路网工具（`slam_ctl.py`、`carto_ctl.py`、`build_from_track*.py` 等）未入库，需要可另行索取；
- AI 助手、终端、巡航仍以离线测试为主，实车未逐项复验；
- 两台车的夹取标定需各自重标一次（换轮/换车后姿态会变）。

## 10. 交接注意事项

- **改配置前先停 APP**：APP 运行中会重写 `settings.json`。
- **改代码后重启 APP**：导航、车体尺寸、路网校验都在内存里。
- **实车操作安全**：手放「停止全部」；窄道速度 0.03~0.04；零余量模式（254）可能擦碰夹爪/轮子。
- **车辆切换**：顶部栏选档案 + 连接方式；身份核对通过才是一一对应的车。2 号车 `HW-A0857935`、1 号车 `HW-10CCA58E`，序号后 8 位即档案号。
- **git**：本分支 `feature/sandbox-nav-handover-20261103`，基于 `main@24a6bdd`；没有强推，`main` 保持不变。合并前先跑分模块测试。
- **备份**：`.work/` 内有各阶段备份与验证记录（不入库），需要回滚可查 `.work/建图记录_20261031.md`、`.work/导航工程_20261101.md` 等。
