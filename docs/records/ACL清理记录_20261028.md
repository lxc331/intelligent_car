# DSH 沙箱 ACL/完整性标签清理记录（2026-10-28）

## 背景
DSH 以 workspace-write 打开工作区时，会对工作区根目录做三类改动并经继承扩散到整棵树：

1. 给按路径生成的合成 SID（`S-1-4-*`，workspaceWriteSid）授予 `Write, Delete, DeleteSubdirectoriesAndFiles`；
2. 给 `Everyone` 加 `FILE_DELETE_CHILD` 拒绝项（SDDL 形如 `(D;CI;DT;;;WD)`）；
3. 给目录打 `Low Mandatory Level (OI)(CI)(NW)` 完整性标签。

这些改动不影响 Authenticode 签名与 Mark-of-the-Web，因此**与“无法验证的发布者”提示无因果关系**（本工作区 MOTW=0，DSH 三个 exe 签名均 Valid）。

## 四、防复发

1. 不要把“已安装程序 / 需要长期信任 / 体积巨大”的目录注册为 DSH 工作区；项目代码单独目录。
2. DSH 每个新工作区根都会重新加授权与 Low 标签（按设计常驻、不自动回收），所以清理是治标；换目录是治本。
3. 合成 SID 无法用 `icacls` 回收（ERROR_NONE_MAPPED 1332），需用 DACL-only 原生 API（本记录中的 P/Invoke 方式）。
