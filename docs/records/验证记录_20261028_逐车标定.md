# 逐车舵机标定（2026-10-28）

## 1. 结论

2 号车（HW-A0857935）的云台俯仰方向、限位、升降臂行程都和 1 号车不同。原来两台车共用一套
`servo` 参数，切到 2 号车会出现「想抬头结果低头」「抬到顶顶到机械限位」。现在把实测值写进
`app/carapp/config.py` 的 `CALIBRATIONS` 表，按 `car.profile_id` 生效，覆盖 `settings.json` 里的
同名项，之后仍过一次安全包络夹取。

**没有改默认值 `SAFE_LIMITS`**：它是两台车共同的硬上限（pitch 1150–2250 已覆盖 2 号车的 1800），
逐车限位在它里面再收窄。所以 `test_control_safety` 里「旧限制不能绕过安全包络」的断言保持不变。

## 2. 2 号车实测数据

### 2.1 云台俯仰（pitch，yaw 先复位 1500）

| 数值 | 画面 | 检测结果 |
|---|---|---|
| 1180 / 1220 | 仰过头，只见天花板 | 灯在画外 |
| 1260 | 灯在画面底部 | red 0.50，box (347,390,25,22) |
| 1300 | 灯在画面下部 | red 0.53，box (347,401,26,23) |
| 1380 | 灯在画面中部 | red 0.59，box (346,288,25,23) |
| 1400 | 灯偏上 | red 0.46，box (347,252,22,24) |
| 1450 | 平视，灯在画面上部 | 该姿态 red False（灯被画面上沿切掉） |
| 1560 / 1600 | 低头，能看到车头前的停止线（1600 时斑马线压画面底部） | — |
| 2050 | 直接怼进夹爪 | — |

结论：**数值越大摄像头越低**（与 1 号车相反）。三档视角取 前视 1450 / 俯视确认停止线 1600 / 仰视看灯 1380。

### 2.2 云台水平（yaw）

1100 往右、1500 正对（灯居中）、1900 往左 → **数值越大越左**，和 1 号车一致，限位不变。

### 2.3 升降臂、夹爪

摄像头在 pitch 1600 时看不到夹爪（1250/1600/1950 三张帧地平线只上下微移），无法自证方向；
夹爪 1550/2000 两张帧也没有可见差异。这两项改为用户现场观察确认。

## 3. 用户给出的最终值（m02014）

> 云台俯仰变化为 1150-1800，方向为由仰视到俯视；云台水平参数不变，方向为数值越大越左；
> 升降臂大概 1300 时候最高，最低应该低于 2000；夹爪没问题。

## 4. 实现

- `app/carapp/config.py`
  - 新增 `CALIBRATIONS`（`HW-10CCA58E` 保持原值；`HW-A0857935` 为实测值），每台车一段
    `servo.limits / actions / presets / signs` + `traffic_light.dip_pitch / confirm_pitch / restore_pitch`。
  - `DEFAULTS["servo"]["signs"] = {"pitch": 1, "yaw": 1}`，含义：数值增大的方向（pitch +1 = 更仰视，yaw +1 = 更左）。
  - 新增 `apply_calibration(cfg)`；`load_config` 改为
    `normalize_connection_config(normalize_servo_config(apply_calibration(cfg)))`。
- `app/carapp/core/teleop.py`：云台方向键按 `signs` 修正步长方向，`I/J` 始终表示「更仰视 / 更左」，
  步长 40，仍按本车限位夹取。
- `app/config/settings.json`：用带标定的配置回写一次（car.profile_id=HW-A0857935，pitch 限位 1150–1800、
  look_down 1600、look_forward 1450、traffic_light 视角 1600/1380/1450、signs.pitch=-1）。
  回写只是让文件反映生效值，切回 1 号车时标定表会再覆盖。

## 5. 行为约定

1. 标定表按当前 `car.profile_id` 生效；表里没有的车辆保持配置文件里的值，不会报错。
2. 标定值覆盖 `settings.json` 的同名项（而不是只补默认值），避免旧文件把方向带反。
3. 覆盖后仍走 `normalize_servo_config`：限位与安全包络取交集，快捷动作、预设都夹在本车限位内。
4. 预设整体替换为标定表里的四套（待机 / 俯视观察 / 夹取准备 / 抬起持物），旧的同名键不会残留。
5. 红绿灯三档视角也随车：1 号车 1720/1450/1500，2 号车 1380/1600/1450。

## 6. 验证

- 新增 `app/tests/test_servo_calibration.py` **12 例**：
  两车限位/动作/预设/视角差异、未知车辆保持原值、标定覆盖旧文件值、预设整体替换且全在限位内、
  `load_config` 按 profile 选表并用 settings.json 里的旧值做对照、`signs` 后遥控方向（1 号车 `I` 增大、
  2 号车 `I` 减小）、2 号车 pitch 夹在 1150–1800、yaw 两车都是「数值越大越左」。
- 全量回归 `.work/run_tests_per_module.py`：**modules=42 ok=42 bad=0**（原 41 + 新增 1）。
- App 侧离线核对：`JunctionViews` 的 1150–2250 校验仍接受 2 号车的 1380/1600/1450；`teleop` 云台步长在
  2 号车上按 -40 走，到 1800 停住。

## 8. 风险与待办

1. 1 号车的参数是 2026-10-23 用户核对过的原值，本轮没有重新实测；1 号车回来后建议复测 pitch 上限
   和升降臂 1300 处是否顶到限位。
2. 2 号车升降臂「最低应低于 2000」是用户估计值，取 1950 为最低动作值、限位下限 1250；如果实测顶到
   机械结构，把 `CALIBRATIONS["HW-A0857935"]["servo"]["limits"]["arm"]` 下界调大。
3. 换车动作（顶部下拉切换）后会重新 `load_config`，但正在按住的方向键不会重放；实测时先切车再操作。
4. `settings.json` 回写会带上 `traffic_light` 整段，属于正常现象（缺失项本来就由默认值补齐）。
