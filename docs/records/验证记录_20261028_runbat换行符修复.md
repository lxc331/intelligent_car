# 验证记录 · run.bat 双击报错（换行符）修复 · 2026-10-28

## 结论一句话

`app/run.bat` 与 `app/tools/设置本机网卡IP.bat` 在交付的 zip 里被转成了 **LF 换行**（原 GitHub 版本是 CRLF）。cmd.exe 无法正确解析 LF-only 批处理，会把文件按错误偏移切行、把半截内容当命令执行，于是出现 `'痌' 不是内部或外部命令` / `'ho' 不是…` / `No suitable Python runtime found` 等一串乱码报错。改回 CRLF 后双击可正常启动 GUI。

## 现场证据（修复前）

| 检查 | 结果 |
|---|---|
| `app/run.bat` | 878 B、GBK、无 BOM、CR=0、LF=37 → **全 LF** |
| `.work/origin/app/run.bat`（GitHub `2342aff` 的 clone 检出） | 915 B、CRLF=37 → 正常 |
| `app/tools/设置本机网卡IP.bat` | 1371 B、LF-only；origin 版 1425 B、CRLF |
| `py -0p` / `py -3 -V` | Python 3.12.10 存在，`py -3` 本身可用（所以不是"没装 Python"） |
| `python -m carapp.main` 导入 | `import tkinter, carapp.main` OK，Tk 8.6 |

两个文件 **只差换行符**：878 + 37 = 915、1371 + 54 = 1425，与 origin 完全对齐。

## 复现实验（对照）

把 `run.bat` 原样复制成两份（仅把 ASCII 的 `carapp.main` 改成等长的 `zzzzzz.zzzz`，保证字节偏移不变、且不会真启动 GUI）：

- `A_lf_gbk.bat`（LF）= 复现故障：cmd 把 `(set`、`errorlevel`、`or:`、`m`、`ython`、`hon`、`ps:`、`双击本文件…` 当作命令执行；
- `B_crlf_gbk.bat`（CRLF，+37 B）= 完全正常：`[启动] 使用 py -3` → Python 报 `No module named 'zzzzzz'` → 进 `:FAILED` 提示块。

→ 故障与内容无关，只与换行符有关。

## 修复

1. 备份到 `.work/backup_pre_fix_runbat/`（两个文件，原 878/1371 B）。
2. 两文件 LF → CRLF（仅插入 0x0D，GBK 字节不动、不加 BOM）。
3. 与 `.work/origin` 对应文件逐字节比对：**identical=True / identical=True**。
4. 新增仓库根 `.gitattributes`：
   ```
   *.bat text eol=crlf
   *.cmd text eol=crlf
   *.sh  text eol=lf
   ```
   仓库里以 LF 存储、检出时转 CRLF，避免再次被工具/压缩包改成 LF。
5. `git add --renormalize -- 'app/*.bat' 'app/tools/*.bat'` 刷新索引 stat；之后 `git status` 里两个 .bat **不再显示为修改**（属性生效，blob 仍是 LF）。

## 修复后验证

- 直接 `Start-Process app\run.bat`（等同双击）→ 12 s 后出现 python.exe 进程，`MainWindowTitle = 小车控制台  ·  ClawPi`、`Responding=True`；测试后已结束该进程（同时确认没有杀到别的 python）。
- `run.bat` 现为 915 B、CR=37、LF=37，首字节 `40 65 63 68 6F 20 6F 66 66 0D 0A`。
- 其他文本文件（README/AGENTS/requirements.json/*.sh/*.txt）仍是 LF-only，对 Windows 无影响，`run.sh` 保持 LF 才能在车上 Ubuntu 运行，未改动。
