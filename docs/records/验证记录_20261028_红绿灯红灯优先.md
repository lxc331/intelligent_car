# 验证记录：红绿灯改为「红灯优先，再确认斑马线」

日期：2026-10-28
相关需求：用户反馈「现在这个状态下，明明是红灯却检测不出。以及，当识别到前方是红灯后，再执行摄像头的确认斑马线动作。」

## 1. 结论

- 判停逻辑从「斑马线确认 → 再判红灯」反转为「红灯独立成立 → 云台俯视确认斑马线 → 两者同时成立才停车」。
- 车已经停在停止线、前视画面里没有斑马线时，只要看到红灯，云台会先压到 1450 俯视找回斑马线，确认到即判停，不再因为 `crosswalk_active=False` 把红灯吞掉。
- 保留反向路径：如果先确认到斑马线、画面里没有红灯，仍会抬头复核红灯（原流程）。
- 离线验证全绿：红绿灯 4 个模块 73 例 OK，全量 41 个模块 41 OK（P0 追加见第 9 节）。
- 实车尚未复测（用户换机、车已离线，`192.168.167.136:8080` 超时）。

## 2. 行为变更

| 项目 | 旧 | 新 |
| --- | --- | --- |
| 红灯成立条件 | `active and red_area > red_area_min` | 只看 `red_area > red_area_min`（+`red_frames`/`red_hold`），与斑马线无关 |
| 停车条件 | `red_required = active and red` | 不变（仍要求路口确认），但红灯不再被门控 |
| 新状态 | — | `red_pending`：红灯已成立、路口未必确认（`snapshot()` 暴露） |
| 云台动作 | 确认斑马线 → 抬头 1720 → 红灯消失/超时回前视 | 前视见红灯 → 压下 1450 确认斑马线（`confirm_dip` 1.2 s）→ 抬头 1720 监控 → 红灯消失 1.4 s 回前视；先见斑马线时仍直接抬头 |
| 提示文案 | 「路口抬头确认红绿灯」「红灯未满足路口条件」 | 「前方红灯，俯视确认斑马线」「斑马线确认，抬头确认红灯」「红灯确认，斑马线前停车」「未确认斑马线，云台复位」「离开路口，云台复位」 |

## 4. 参数

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `red_area` | 450 px² | 红灯面积门限（折算 640×480） |
| `red_frames` | 2 | 连续确认帧数 |
| `red_hold` | 1.5 s | 短暂漏检保持：覆盖云台压下确认斑马线（最长 1.2 s 看不到灯）和 LED 闪烁，避免停车中误松刹车 |
| `dip_pitch` | 1450 | 看到红灯后压下的俯角（实测最近斑马线中心 y≈438、置信度 0.96） |
| `confirm_dip` | 1.2 s | 俯视确认斑马线的最长时间，超时回前视 |
| `confirm_pitch` | 1720 | 抬头监控红灯的仰角（实测红灯 0.73、面积 528 px²） |
| `restore_pitch` | 1500 | 前视复位角 |
| `confirm_delay` | 1.4 s | 离开路口/灯灭后回前视的延时 |
| `confirm_hold` | 8 s | 仰视监控 8 s 一直没读到红灯就回前视重试（`confirm_retry` 后再抬） |
| `confirm_retry` | 0.8 s | 回前视后重试间隔 |

   - 第 1 帧：前视红灯面积 506 → `red_pending` 成立；
   - 第 2 帧：动作 `dip`，提示「前方红灯，俯视确认斑马线 1450」；
   - 第 5 帧：俯视帧确认斑马线（`crosswalk_active=True`）→ 动作 `lift`，提示「斑马线确认，抬头确认红灯 1720」，当帧即 `blocked=True`；
   - 第 6–8 帧：仰视红灯面积 550 → `blocked=True` 持续，`stopped=True`、最终视角 `lift`、pitch 1720。
   - `red_hold` 由 0.6 s 调到 1.5 s 的原因：压下确认期间（最长 1.2 s）看不到灯，0.6 s 会让 `red_pending` 在抬头前掉一帧，重放里可见「第 5 帧 pending 变 False → blocked 抖动」；调到 1.5 s 后重放全程 `blocked=True` 连续。
5. 离线实车帧（`.work/traffic_light_live/`）曾验证：前视顶部带红灯 0.40–0.63、停车位俯视斑马线 0.96、抬头红灯 0.68–0.78；本改动不改变检测器，只改变判定顺序。

## 7. 风险与待办

- **未实车复测**：改动的核心价值是「停在停止线时红灯能判停」，需要车恢复在线后跑 40 帧演练确认 DIP→LIFT 时序与刹车保持。
- 红灯→压下的动作会在红灯可见但离斑马线还远时反复「压下—回前视」（每次 1.2 s + 0.8 s 重试），观感上云台会动；确认到斑马线后即稳定抬头。
- 误检兜底仍依赖「红灯 + 斑马线同时成立」；红色锥桶单独出现只会在提示区显示「前方红灯，确认斑马线」，不会停车。
- `red_hold` 0.6 s 对「停车后灯刚好离开画面」的保持偏紧，实测若出现短暂松刹车，可调到 1.2–1.5 s（`settings.json` 改后重启生效）。
