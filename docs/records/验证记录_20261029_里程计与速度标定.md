# 验证记录：里程计真实性、麦轮运动学与速度比例（2026-10-29）

## 结论

1. **车端 `/odom` 不是轮速反馈，而是按 `cmd_vel` 积分出来的假里程计。**
   - 厂家源码 `.work/vendor_src/src/driver/controller/controller/odom_publisher_node.py` 的 `cal_odom_fun()`：
     `delta_x = self.linear_x * self.dt * math.cos(self.pose_yaw)`、`delta_y = ...`、`delta_yaw = self.angular_z * self.dt`，
     其中 `linear_x/linear_y/angular_z` 就是 `cmd_vel_callback()` 存下来的**指令值**，没有读轮子编码器。
   - 实测印证：停止时 `/odom` 位姿不动；发 `linear.x=0.06` 1.5 s，`/odom` 位移 ≈ 指令×时间。
   - 影响：`/odom` 不能当"真实位移"用；但它可以当"指令积分"，配合 `speed_scale` 换算真实米数。
2. **底盘是麦轮 X 型**（`mecanum.py` 的 `MecanumChassis.set_velocity`）：
   `motor1 = vx - vy - wz*(wheelbase+track_width)/2`，`motor2 = vx + vy - ...`，`motor3 = vx + vy + ...`，`motor4 = vx - vy + ...`，
   尺寸 `wheelbase=0.1320, track_width=0.1410, wheel_diameter=0.059`。纯 `linear.x` 时四轮同速 → 应当直行。
   注意 `cal_odom_fun()` **完全忽略 `linear_y`**，所以横移时 `/odom` 不会有位移。
3. **真实速度 ≠ 指令速度**：用车前路障（雷达前向 1.078 m 作为停止线参考）实测，指令 `0.06 m/s` 跑 1.5 s，
   雷达读数 1.289 → 1.121 m，真实位移 0.168 m → **真实速度 0.112 m/s，比例 1.87**。
   - 之前"停车过冲 0.38 m"的原因就是拿指令积分当真实位移：程序以为走了 0.28 m，实际走了约 0.6 m。

## 代码改动

  `CrosswalkApproach.step()` 里 `used = (travel - trigger_start) * speed_scale`，再与 `finish_travel` 比较；
  参数校验新增「实际速度比例无效」。

- 测试：`app/tests/test_junction_drive.py` 新增「速度比例参与收尾计算」「默认配置带实测比例」两例，
  参数非法用例加入 `speed_scale: 0`；路口+测距两模块 37 例通过。

## 待补

- `speed_scale` 只测了 0.06 m/s 一个点；0.10 / 0.12 m/s 需要各测一次（换车后要重测，两台车可能不同）。
- 麦轮直行左右偏：属于机械/地面问题，控制层用 `/odom` 的 yaw 做保持（`/odom` 的 yaw 也是指令积分，
  所以只能保持"指令航向"，不能纠正真实跑偏）；真实偏航要靠视觉或雷达对称性判断。
- 低电压保护：用户反馈 6.8 V 以下触发报警，测试脚本应在开始前读取电压并拒绝运行（待接 `ros_robot_controller` 的电压话题）。
