## 一、夹取流程（先搞清在哪一步出事）

```
start_pick <颜色>
   └─ COLOR_INITIAL_CHECK   0.5s 看当前视野有没有目标
        └─ 没有 → COLOR_SCAN_TO_START + COLOR_SCANNING  云台 650→2250 扫视（步长 20，每 0.05s）
   └─ 连续 3 帧检出 → COLOR_BASE_ALIGN   底盘按云台偏移量转向
        └─ COLOR_ALIGN   先左右对准（误差 28px 内），再前进到抓取线
             └─ cy ≥ COLOR_PICK_Y → 合爪 → PICKING_CLOSE(0.45s)
                  └─ 抬臂 → PICKING_RAISE(0.65s) → HOLDING
place_down   → 落臂 → 松爪
place_on_hand → 抬头找人脸 → 对准 → 前进 5cm → 松爪
stop         → 回初始位
```

## 二、可调参数（按"出问题先动谁"排序）

### 1. 颜色阈值 —— 80% 的"找不到/找错"都是这里

文件：`/home/ubuntu/software/lab_tool/lab_config.yaml` → `lab.Mono.<颜色名>.min/max`（OpenCV Lab，三通道）

现成的颜色名只有 6 个：`black / blue / dark_green / green / red / white`

**注意两个坑：**

- **`dark_green` 的阈值是全 0–255**，等于"匹配一切"，选它必然满屏命中。
- **没有 `yellow`**（yellow 只在 `Stereo` 段里有），车上是单目摄像头，走的是 `Mono` 段 → 说"夹黄色"会直接报 `unknown color`。
- `black` 上限 L=89，也很宽，容易误检地面阴影。

调法：用容器里 `~/software/lab_tool` 的取色工具对着实物取值，或我直接给你算一份新的 min/max 填进去。

### 2. 抓取距离 —— 最影响"夹空/夹到边"

| 常量 | 当前值 | 作用 |
|---|---|---|
| `COLOR_PICK_Y_RATIO` | 365/480 | 抓取线在画面中的高度比例 |
| `COLOR_PICK_Y` | 由上式算出 ≈ 91（在 320×120 处理图上） | **像素 cy 到这里才合爪**，越小=越早夹（离得远），越大=越晚夹（贴最近） |
| `COLOR_MAX_LINEAR_X` | 0.18 m/s | 接近速度上限 |
| `COLOR_MAX_APPROACH_SECONDS` | 5.0 s | 超时不出 `COLOR_APPROACH_TIMEOUT` 就放弃 |

### 3. 爪子／手臂 PWM（范围 500–2500，1500 中位）

| 常量 | 值 | 含义 | 症状 → 调整方向 |
|---|---|---|---|
| `SERVO_GRIPPER` = 4 | `GRIP_OPEN 2200` | 张爪 | 张不开 → 增大（往 2300+） |
| | `GRIP_CLOSE 1700` | 合爪 | 夹不紧/夹起就掉 → 增大（往 1800–2000） |
| `SERVO_ARM` = 3 | `ARM_DOWN 1200` | 臂放下（贴地取） | 爪子够不到地 → 减小 |
| | `ARM_PICK_UP 1700` | 夹住后抬起 | 抬得不够高 → 增大 |
| `SERVO_PITCH` = 1 | `PITCH_COLOR 1300` | 相机俯角（看地面） | 老看不到方块 → 微调 |
| | `PITCH_HEAD 1800` | 相机抬头（看人脸） | 送人手势识别不到 → 调 |
| `SERVO_YAW` = 2 | `YAW_INIT 1500` | 云台中位 | |
| | `YAW_SCAN_START 650` / `YAW_SCAN_END 2250` | 扫视左右极限 | 身后有方块扫不到 → 扩极限 |
| | `YAW_SCAN_STEP 20` / `YAW_SCAN_PERIOD 0.05` | 扫视速度 | 扫太快漏检 → 步长减小 |

### 4. 视觉稳定性

| 常量 | 值 | 作用 |
|---|---|---|
| `PROCESS_SIZE` | (320, 120) | 检测用的缩小图分辨率；太大会掉帧 |
| `COLOR_MIN_CONTOUR_AREA` | 80 | 最小色块面积；小方块检不到 → 调小；误检 → 调大 |
| `COLOR_FOUND_STABLE_FRAMES` | 3 | 连续几帧才认定"找到"；抖动 → 调大 |
| `COLOR_LOST_STABLE_FRAMES` | 3 | 连续几帧才认定"丢了" |
| `COLOR_ALIGN_X_TOLERANCE` | 28 px | 左右对准容差（相对 `COLOR_CENTER_X = 180`） |
| `COLOR_REACQUIRE_WAIT_SECONDS` | 2.0 s | 跟丢后原地等多久再重新扫 |

### 5. 底盘对准

| 常量 | 值 | 作用 |
|---|---|---|
| PID 角速度 | P=0.012 | 左右转的力度 |
| PID 前进 | P=0.003, I=0.0001 | 前进的力度 |
| `BASE_ALIGN_ANGULAR_Z` | 0.60 rad/s | 底盘补偿云台偏移时的转速 |
| `BASE_ALIGN_SECONDS_PER_PULSE` | 0.0025 | 每 PWM 单位补多少秒（转多了／转少了调这个） |

### 6. 放置 / 送人

| 常量 | 值 |
|---|---|
| `PLACE_SPEED` / `PLACE_DISTANCE_METERS` | 0.10 m/s / 0.05 m |
| `PLACE_ACTION_INTERVAL_SECONDS` | 0.8 s |
| `FACE_DETECTION_WIDTH` | 320 |
| `HEAD_ALIGN_X_TOLERANCE` / `Y_TOLERANCE` | 10 / 16 px |
| `HEAD_FOUND_STABLE_FRAMES` | 3 |
| `HEAD_CAMERA_RAISE_SECONDS` | 0.45 s |

## 三、怎么触发（不改代码）

```bash
# 进容器
sudo docker exec -it -u ubuntu ClawPi zsh
source /opt/ros/humble/setup.bash; source ~/ros2_ws/install/setup.bash

# 夹一个红色方块（debug 模式下一步到底）
ros2 service call /color_track_pick/start_pick interfaces/srv/SetString "{data: red}"

# 放下 / 送到人手上 / 中止
ros2 service call /color_track_pick/place_down   std_srvs/srv/Trigger
ros2 service call /color_track_pick/place_on_hand std_srvs/srv/Trigger
ros2 service call /color_track_pick/stop          std_srvs/srv/Trigger

# 看状态
ros2 topic echo /color_track_pick/state_topic
ros2 topic echo /color_track_pick/picked
```

## 四、跟助手怎么提需求（模板）

**最短一句**：`夹红色的方块`

**调参时给这三样**就够我动手：

1. **现象**（在第几步、看到什么）：例如"扫视扫不到"、"夹起来掉"、"夹到方块边上"、"超时了"
2. **期望**：例如"再靠近一点夹"、"夹得更紧"、"扫视范围放大"
3. **约束**：现场有没有实物、允不允许底盘转/前进、要不要先备份

> 参考句式：
> 「车夹红色方块时夹空了，想让它再往前贴近一点再合爪，底盘可以动，你先备份再改」

**我这边默认会做**：改动前 `cp` 备份到 `~/wb_backup/<时间戳>/` → 改常量/改 yaml → 重启 `start_node` 或单独重启该节点 → 抓 `/color_track_pick/image_result` 画面给你确认 → 失败可一键回滚。
