# 小车控制台（ClawPi Console）

用于两台 ClawPi 智能小车的 Python 桌面控制程序，集成夹取、颜色追踪夹取、鼠标/键盘遥控、原厂雷达三模式、沙盘二维建图、实时视频和 SSH 终端。

桌面程序位于 [`app/`](app/)，独立摄像头预览工具位于 [`tools/`](tools/)。本文路径均以项目根目录为起点；需要进入 `app/` 运行的命令会单独标明。

## 功能概览

| 页面 / 功能 | 当前支持 |
|---|---|
| 夹取 + 实时画面 | 底盘点动、舵机快捷动作、四路滑杆、预设姿态、定时夹取序列、颜色追踪夹取 |
| 远程遥控 + 实时画面 | 鼠标按住控制、键盘控制、前后移动、左右横移、原地转向、云台和夹爪操作 |
| 自动巡航 + 实时画面 | 厂家雷达避障、雷达跟随、雷达警卫，单检测距离与速度设置，自动本机记录 |
| 沙盘建模 + 实时展示 | 复用车端 SLAM Toolbox，鼠标/键盘遥控，地图与视频并排显示，地图双端保存 |
| 集成终端 | SSH 交互命令行、进入 ClawPi 容器、宿主机/容器目录浏览、文本文件只读预览 |
| 两车连接 | 车辆档案、有线/AP 热点/STA 局域网切换、服务搜索、连接诊断、ROS 与视频断线重连 |
| 视频与记录 | 图像话题切换、识别框与标定线、抓帧、本机录像、视觉夹取运行记录 |

基础控制通过 rosbridge，视频通过 web_video_server；电脑无需安装 ROS 或 OpenCV，也不需要向小车部署配套服务。集成终端使用小车已有的 SSH，输入的命令会在远端实际执行；右侧文件浏览区只提供读取和预览。

## 安装与启动

### 1. 准备 Python 与依赖

建议使用 Python 3.10 或更高版本，并确保包含 Tkinter。完整功能的依赖见 [`app/requirements.txt`](app/requirements.txt)：

| 依赖 | 用途 |
|---|---|
| Pillow | JPEG 显示、颜色识别与视觉追踪夹取 |
| Paramiko | SSH 连接与远端文件查询 |
| pyte | 终端控制序列解析、屏幕与滚动历史 |

在项目根目录执行：

```bash
python -m pip install -r app/requirements.txt
```

安装依赖和启动程序应使用同一个 Python 环境。基础手动控制可不安装这些可选依赖：缺少 Pillow 时视频使用 PNG/Tk 模式，视觉追踪不可用；缺少 Paramiko 或 pyte 时集成终端不可用。

### 2. 连接小车

| 车辆 | 有线固定地址 | Wi-Fi 热点名称 | 热点地址 |
|---|---|---|---|
| 1 号车 | `192.168.150.3` | `HW-10CCA58E` | `192.168.149.1` |
| 2 号车 | `192.168.150.2` | `HW-A0857935` | `192.168.149.1` |

有线地址依据现有两车档案中的 NetworkManager 持久配置。旧记录中的 `ip addr add` 只是临时添加地址，重启后可能失效，不应作为固定地址依据。

**有线连接：** 接好小车网线，在电脑对应的有线网卡上设置以下参数；不要修改用于校园网或上网的其他网卡。

| 参数 | 值 |
|---|---|
| 电脑 IPv4 地址 | `192.168.150.100`（确保没有被其他设备占用） |
| 子网掩码 | `255.255.255.0` |
| 默认网关 | 留空 |
| DNS | 留空 |

也可右键以管理员身份运行 [`app/tools/设置本机网卡IP.bat`](app/tools/设置本机网卡IP.bat)，按提示选择有线网卡。两车通过交换机同时在线时，可在 App 中选择要控制的一台，无需重新给车改地址。

**Wi-Fi 连接：** 先在系统中连接目标车辆的热点，电脑地址由热点 DHCP 分配，再在 App 顶部选择对应车辆和“Wi-Fi 热点”。两车热点地址相同，App 会核对 SSID；未识别或不匹配时不会建立连接。Windows 使用 `netsh` 读取 SSID，Linux 需要 `iwgetid`；无法读取时先解决系统权限/工具问题，或使用有线连接。热点凭据请查看本地账号资料。

**STA 局域网连接：** 先把小车配置成连接外部路由器/热点，再让电脑接入同一局域网。在顶部选择车辆和“STA 局域网”，填入小车获得的无线 IPv4 地址后点“应用”；首次没有保存地址时会提示输入。1 号车本次连接 2.4 GHz 网络 `Win11_Meng_plus`，获得 `192.168.137.149`，已验证电脑通过无线 SSH 和视频访问；电脑连接 `Win11_Meng_plus_5G` 时也已验证互通。2 号车上次保存的地址为 `192.168.137.192`，本次未重新验证。地址来自 DHCP，后续可能变化，可更新地址或使用“自动搜索”。

STA 旁的 Wi-Fi 名称可选，仅供记录和诊断，不要求电脑连接 `HW-*` 小车热点，也不保存 Wi-Fi 密码。两车分别保存 STA 地址；切换模式保留原有线和 AP 地址。这个下拉框选择的是 App 访问方式，**不会直接切换小车的 AP/STA 模式，也不会替电脑连接 Wi-Fi**。

**在 App 中更换小车连接的 Wi-Fi：** 点击顶部“配置小车 Wi-Fi”，输入新的网络名称和密码，再点“下发并连接”；开放网络勾选“开放网络（无 Wi-Fi 密码）”。电脑须能通过网线、原局域网或小车热点访问当前车辆，推荐用网线保留切换时的管理通道。下发前会核对车辆身份并备份原配置；支持的车端恢复服务会自动尝试新网络，失败临时回退 AP 并继续重试。确认新地址可达后可自动切换 App；若原连接中断，先让电脑接入目标局域网，再点“查找新地址”。完全离线时须先恢复一条管理连接。

下发的新网络同时作为该车的**开机首选**保存在车端，App 会读回校验网络名称、密码与 STA 模式，并检查、必要时启用 `wifi.service` 开机自启。仅在保存、自启和服务运行均确认后显示“已保存为开机首选”。下次小车启动会先尝试这个网络，临时回退 AP 不会清除它；再次下发其他网络会替换首选。顶部普通“应用”只保存 App 的访问地址和 Wi-Fi 名称提示，修改开机首选须使用“配置小车 Wi-Fi → 下发并连接”。

Wi-Fi 和登录密码只用于当次操作，不写入 `settings.json` 或日志。原配置备份和可用的摄像头录像保存在电脑 `.work/wifi_setup/`，备份含原有凭据，请仅在本机保留。开放网络若需要兼容旧版恢复模块，App 只会更新已识别版本的 `wifi_recovery_adapter.py`，并仅重启 `wifi.service`；自定义版本会提示先升级，不自动覆盖。需要 `paramiko` 及完整项目的 `tools/vehicle_network/` 部署源文件。网络仍需允许设备相互访问，网页登录或企业认证网络可能还需额外配置。

**车端 STA 自动恢复：** 两台车均已部署“STA 优先”恢复服务，各自保留 `HW-10CCA58E` / `HW-A0857935` AP 名称。启动或掉线后默认尝试连接 120 秒，失败时临时提供小车 AP 热点，保留原来的 STA 偏好；随后每 60 秒重试 STA，单次尝试约 25 秒，成功后回到局域网。1 号车已实测默认 120 秒失败后临时回退 AP。单张无线网卡切换角色时会暂时中断 AP。用户明确选择手动 AP 时保持 AP，不自动切回 STA。**断电冷启动尚未实测**；实现、配置与回滚方式见 [车端 Wi-Fi 恢复服务](tools/vehicle_network/README.md)。

### 3. 启动程序

Windows 双击 [`app/run.bat`](app/run.bat)。Linux / macOS 在项目根目录执行：

```bash
bash app/run.sh
```

也可使用命令行，先进入 `app/`：

```bash
cd app
python -m carapp.main
python -m carapp.main --host 192.168.150.2
python -m carapp.main --transport sta --car HW-A0857935 --host 192.168.137.192
python -m carapp.main --tab gripper
python -m carapp.main --tab remote
python -m carapp.main --tab cruise
python -m carapp.main --tab terminal
```

`--host` 覆盖本次启动地址；在界面中应用地址或切换车辆会保存配置。使用热点时优先通过车辆和连接方式选择，不能仅凭共享 IP 区分车辆。

小车刚开机通常需要约 40–60 秒启动业务服务。App 会持续尝试连接当前选择的车辆；顶部显示 ROS 已连接并收到新画面后再操作。

## 两车切换、搜索与重连

- 顶部车辆下拉显示车号和硬件标识；切换有线、AP 热点或 STA 局域网方式时会填入该车分别保存的地址。
- “应用”可使用手动填写的地址；“自动搜索”在 STA 下优先搜索当前无线网段及保存地址所在网段，过滤常见虚拟网卡，限制为最多四个 `/24`。有线/AP 沿用配置中的搜索网段。搜索结果是端口候选，仍由用户确认车辆后选择，不据此自动判定身份。
- “连接诊断”显示目标地址、本机 IPv4、热点 SSID 和图像/ROS 服务端口状态。Windows 可读取详细网卡信息；诊断不修改网卡或车端配置。
- ROS 与摄像头分别自动重连，ROS 使用心跳检测失活连接；不会因为另一台车在线而自动换车。
- 断线时取消当前动作并清除旧状态；重连后恢复状态订阅并发送停车指令，不重放运动或夹取动作。网络已断开时不能保证停车指令送达实车。
- 动作序列执行中不能直接换车，应先中止并等待结束。切车会关闭旧 SSH 会话，终端需重新连接。

## 夹取与视觉追踪

### 手动控制与定时夹取

夹取页支持慢/中/快三档速度（默认配置为 `0.06 / 0.10 / 0.15 m/s`），前后移动、左右转向、左右平移、前后 `0.3 s` 点动和停止。按住按钮持续移动，不设单次时长上限，松开或移出按钮后停止。

四路舵机提供快捷动作、滑杆和预设姿态；滑杆调整后点击“应用全部”下发。所有舵机目标均通过统一限位检查，越界请求整条拒绝。

| 关节 | 通道 | App 允许范围 | 当前快捷位置 |
|---|---|---|---|
| 云台俯仰 | CH1 | `1150–2250` | 俯视 `1300`、前视 `1500` |
| 云台水平 | CH2 | `650–2350` | 中位 `1500` |
| 升降臂 | CH3 | `1200–2000` | 抬起 `1200`、降下 `1700` |
| 夹爪 | CH4 | `1500–2000` | 张开 `2000`、半开 `1750`、闭合 `1500` |

这些数值是舵机控制位置，不代表夹持力。云台物理范围两端各预留 150；俯视/前视方向按现有 2 号车实测记录配置，1 号车的相机方向和实际夹取位置仍应单独核对。

“一键夹取（车轮配合）”按以下顺序执行：

```text
张爪 → 降臂 → 前进 N 秒 → 合爪 → 抬臂 → 后退 M 秒
```

前进/后退默认 `0.6 / 0.4 s`，可在界面修改。该流程按时长运动，不根据图像修正距离；“中止”会取消后续步骤并发出停车指令。

### 颜色追踪夹取

支持红、绿、蓝、黄四种颜色，在电脑上处理 `/image_raw` 画面，通过目标中心与已标定夹取线控制转向和接近。

首次使用某台车、某种颜色或改变准备姿态时：

1. 选好车辆，确认 ROS 与 `/image_raw` 新画面可用，选择目标颜色。
2. 点击“① 视觉准备”，等待云台、升降臂与夹爪到准备位置。
3. 将目标实际放在张开的两爪之间，等识别框稳定，点击“② 两爪间标定”。不要用远处目标标定。
4. 保持相机和准备姿态不变，将同一目标放远，仍保持在视野内，点击“一键追踪夹取”。
5. 程序对准、接近、停车合爪并抬升；需要停止时点击“中止追踪”。

标定会检查近端位置、目标尺寸、版本和准备姿态；不合格的旧标定需重新制作。标定按车辆档案、连接地址和颜色保存，两台车不共用热点标定；切换有线/热点地址后也可能需要重新标定。仅改变同一目标的远近，无需重新标定。

默认追踪参数：最大速度 `0.06 m/s`、转向 `0.30 rad/s`、接近阶段最长 `45 s`、累计里程上限 `0.8 m`。画面超过 `0.6 s` 未更新时停止移动，目标丢失超过 `2 s`、里程计超过 `0.8 s` 未更新、里程突变或 ROS 断线时终止。实际值以配置为准。

项目已有 2026-10-23 的 2 号车红色目标夹取成功记录，但程序没有夹持传感器或独立的抓取成功检测；“动作完成”后仍需观察是否夹住。

## 远程遥控

“远程遥控 + 实时画面”提供两种模式：

- **鼠标点击操控：** 底盘与云台按钮按住连续控制，松开或移出按钮即停；升降臂和夹爪单击执行。
- **键盘操控：** 先选键盘模式，再点击“点击启用键盘操控”，使控制区域获得焦点。点击其他输入框、切换页面或窗口失焦会退出键盘控制。

| 按键 | 功能 |
|---|---|
| `W / S` | 前进 / 后退 |
| `A / D` | 原地左转 / 右转 |
| `Q / E` | 向左 / 向右横移，车头方向保持不变 |
| `I / K` | 云台仰视 / 俯视微调 |
| `J / L` | 云台水平左转 / 右转微调 |
| `T / G` | 升降臂抬起 / 降下 |
| `F / H` | 张开 / 闭合夹爪 |
| `空格 / Esc` | 停止并退出键盘操控 |

界面中的“平移左转 / 平移右转”按钮对应横移。可组合底盘按键，斜向移动会归一化速度。底盘和云台按住持续控制，不设单次时长上限，松开即停止连续指令。切换模式、页面、车辆或失去窗口焦点会停止控制；夹取动作未结束时不能同时遥控。

云台微调依据最近下发的目标值，首次使用俯视位置和水平中位作为基准，不是舵机实际位置回读。

## 实时画面与本机记录

夹取、遥控和自动巡航页共用当前车辆的视频流。三页的图像话题切换和重连操作作用于同一个流。

| 图像话题 | 用途 |
|---|---|
| `/image_raw` | 原始画面，视觉追踪必须使用此话题 |
| `/color_track_pick/image_result` | 车端颜色抓取调试图 |
| `/line_following/image_result` | 车端循线调试图 |
| `/object_tracking/image_result` | 车端目标跟踪调试图 |
| `/llm_control/image_result` | 车端大模型控制调试图 |

能否收到调试图取决于车端相应节点是否正在发布；选择话题不会自动启动车端算法。

画面按可用空间缩小显示。安装 Pillow 时使用 JPEG，否则使用 PNG/Tk 模式；断流或启动失败后自动重试。原始画面可叠加目标框、中心点和标定线。

默认保存位置由 `camera.save_dir` 控制，相对路径以 `app/` 为基准：

| 内容 | 默认位置 / 格式 |
|---|---|
| 手动抓帧 | `app/捕获/`，JPEG 或 PNG |
| 手动录像 | `app/捕获/预览录像/`，JPEG 模式为 `.mjpg`，PNG 模式为帧序列 |
| 视觉标定图 | `app/捕获/追踪夹取/标定/` |
| 追踪过程 | `app/捕获/追踪夹取/时间戳/`，包含阶段截图、运行记录和程序启动的录像 |
| 自动巡航过程 | `app/捕获/自动巡航/时间戳/`，包含阶段截图、雷达和速度记录、程序启动的录像 |

`运行记录.json` 包含标定、阶段事件、逐步跟踪数据、里程与速度指令、结束原因。如果启动追踪前已有手动录像，追踪不会另外开启一份录像。上述抓帧、录像与运行记录均写在电脑上。

顶部显示 ROS 状态、节点数、电压、里程计位姿、画面尺寸/帧率、夹爪目标和底盘指令。舵机目标和底盘速度是下发记录，不是位置或轮速实测；节点数也会随车端启用的功能变化。

## 集成终端与文件浏览

终端连接当前顶部所选车辆，默认 SSH 用户为 `pi`、端口为 `22`，与 ROS、视频连接相互独立。

1. 进入“集成终端”，输入小车 SSH 凭据，点击“连接 SSH”。
2. 左侧可输入 Linux 命令，支持回车、退格、Tab、方向键及终端控制序列。
3. `Ctrl+C` 中断远端命令；`Ctrl+Shift+C / V` 复制/粘贴，也可使用右键菜单。
4. 在宿主机提示符下点击“进入 ClawPi”，进入现有 `ClawPi` 容器并加载 ROS Humble 与工作区环境。该按钮依赖远端现有的 Docker 和免密 sudo 配置。
5. 右侧选择“宿主机”或“ClawPi 容器”，支持用户目录、上一级、路径跳转、刷新、ROS 源码快捷入口和复制路径。

双击目录进入，双击普通文件预览文本；最多读取前 `256 KiB`，二进制文件仅提示类型和大小。文件浏览通过 SSH 执行只读 Python 查询，不依赖 SFTP，不提供上传、编辑或删除按钮。

如根目录已有本地 `小车账号密码信息.txt`，程序会尝试读取其中密码并填入掩码输入框；该文件不是运行必需项，密码不会写入 `settings.json` 或程序日志。有预填密码且 `terminal.auto_connect` 开启时，首次进入终端页会尝试连接；失败后可手动重连。

首次 SSH 连接会记录主机指纹到 `app/config/ssh_known_hosts`，之后核对密钥；两车共享热点地址时按车辆档案区分记录。切车会断开旧会话，SSH 断线后不自动重放命令。

## 常见问题

| 现象 | 检查方式 |
|---|---|
| ROS 与画面都连不上 | 点击“连接诊断”，核对所选车辆、有线网卡地址或 Wi-Fi 热点；只有校园 Wi-Fi 地址通常无法直连小车 |
| 换车后连不上 | 有线区分 `.3 / .2`；热点方式先切换系统连接的 SSID，再选择对应车辆 |
| STA 局域网连不上 | 核对小车当前 DHCP 地址、电脑和小车是否处于可互访的同一局域网；检查客户端/AP 隔离和服务端口。STA 不使用小车自身热点的 SSID 校验 |
| 开关机后暂时连不上 | 等待车端服务启动；App 会持续重试当前地址。长期不通时检查图像/ROS 端口及车端服务 |
| ROS 已连接但没有画面 | 核对图像话题是否正在发布、8080 是否可达；可用视频栏“重新连接”重启拉流 |
| 有画面但不能控制 | 检查 9090 和 ROS 状态；图像服务与控制服务可以分别故障 |
| 看不到某个算法调试图 | 车端对应算法可能未启动，切换话题不会启动节点 |
| 追踪提示标定无效 | 目标实际放入两爪之间，视觉准备后重新标定；旧版本、远端小目标或姿态变化会被拒绝 |
| 追踪中途停止 | 查看日志和运行记录中的图像、目标、里程计、距离或超时原因，确认后重新启动 |
| 键盘没有控制小车 | 进入遥控页、选择键盘模式并点击启用，使控制区域获得焦点；检查是否仍有夹取动作 |
| SSH 连接失败 | 检查目标、22 端口、凭据、依赖及主机密钥提示；ROS 已连接不代表 SSH 已连接 |
| 容器目录读取失败 | 检查 `ClawPi` 容器是否运行、容器内是否有 Python 3，以及 SSH 用户能否免密执行所用 Docker 命令 |
| 启动提示缺少模块 | 使用启动程序的同一 Python 安装 `app/requirements.txt`；缺少 Tkinter 时需安装带 Tk 支持的 Python |

## 开发与测试

在 `app/` 目录运行无需实车的测试：

```bash
cd app
python -m unittest discover -s tests -v
```

现有测试覆盖连接恢复、控制限位与中止、视觉追踪、远程遥控和集成终端；测试通过不能替代两台实车的逐车校准与现场验证。

新增页面时继承 `app/carapp/features/base.py` 中的 `Feature`，实现 `build()`，按需实现 `on_tick()`、`on_background_tick()`、`on_activate()`、`on_deactivate()`、`on_close()`，然后在 `app/carapp/features/__init__.py` 的 `FEATURES` 列表注册。当前注册顺序是 `GripperFeature`、`RemoteFeature`、`CruiseFeature`、`MappingFeature`、`TerminalFeature`。

界面每轮只调用当前页的 `on_tick()` 绘制视频、地图和终端文本；所有页面的 `on_background_tick()` 继续处理会话结果、许可失效停车和录像收尾。摄像头仍只接收一路共享视频，隐藏面板只保留最新帧，显示时才解码，不改变视频画质和无线带宽设置。

通过 `AppContext` 使用共享状态、日志、视频帧订阅及连接。舵机与底盘操作应走 `publish_servo()`、`publish_twist()` 和 `stop_base()`，复用统一校验；离开控制页时应清理持续动作。

后续开发遵守三条原则：新功能按职责放置，避免继续向大文件堆积；修改单个功能时尽量不影响其他功能；代码反复修改、重复出现或难以测试时，再针对性拆分。具体约定记录在项目根目录 `AGENTS.md`，不进行与当前需求无关的大规模重构。

当前雷达传输与有效性检查在 `carapp/core/laser_scan.py`，厂家三模式数值逻辑独立在 `carapp/core/vendor_lidar.py`，巡航执行及取消机制在 `carapp/core/cruise.py`；`from carapp.core.cruise import LaserMonitor` 保持兼容。跨页面运动占用继续通过 `AppContext.motion_in_use()` 与 `Feature.motion_active` 查询。

`/scan_raw` 通过 `carapp/core/realtime_ros.py` 直接在 ROS 接收线程更新最新数据，不再等待界面队列。该话题的所有数据消费者应在 `realtime_ros_handlers()` 注册纯数据回调，不能操作 Tk 控件；并通过 `reset_realtime_ros()` 清空会话数据。会话锁覆盖更新和重置，断线、切车与退出均使旧扫描失效。其他 ROS 消息保留原有界面派发方式。雷达订阅频率、厂家算法与速度参数沿用原设置；运行中的扫描超时改为零速等待，新扫描恢复后自动继续。


## 自动巡航 + 实时画面

本页直接迁移本地厂家 `ClawPi智能小车/3 源码资料/src/app/app/lidar_controller.py` 的三种雷达模式，不再使用之前的双距离、车体轨迹预测、候选曲率、后侧扇区检查、小缺口补洞、换向确认或 20 秒绕障限时。

### 使用

1. 等待 ROS、实时画面和 `/scan_raw` 就绪。
2. 选择一个模式：**雷达避障、雷达跟随、雷达警卫**。三项互斥。
3. 设置一个**检测距离 0.30–1.50 m**（默认 0.60 m）和**移动速度 0.02–0.15 m/s**（默认 0.06 m/s），应用后点击“启动巡航”。
4. 自动巡航支持后台运行：切换页面或点击其他软件不会取消巡航；顶部一直显示巡航运行/等待状态，可随时点击“■ 停止全部”。手动遥控仍在切页、失焦时停止。巡航占用底盘期间，其他页面不能启动底盘遥控、夹取序列或视觉追踪夹取，须先停止巡航。
5. 切换模式会先停车并结束上一轮录像，需要再次点击启动。修改同模式参数会先归零、重新评估后继续。手动停止、ROS/画面断开、无效雷达数据或指令发送失败仍会取消运行；只有运行中的雷达超时会自动等待恢复。

速度仍以电脑端的米/秒表示，沿用现有可调范围；厂家参数服务只要求速度为正数，本地源码没有提供手机界面 10–100 数值到物理速度的换算，因此没有猜测该比例。算法中的转弯速度、角速度及 PID 限幅均按该物理速度使用厂家公式。

### 检测距离的含义

距离由雷达中心到回波点测量，处理的是配置检测角中的点，不是车体四周必须留出的空间。默认检测角沿用厂家 enter 后的 **90°**，即标准型号前方左右各约 45°。

| 模式 | 检测距离的作用 | 行为 |
|---|---|---|
| 雷达避障 | 左、右检测区最近回波距离 **≤检测距离** 时触发 | 无近障直行，有近障时按厂家 last_act 和定时转弯逻辑同时前进、转向 |
| 雷达跟随 | 检测区最近目标距离 **<检测距离** 时响应 | PID 控制前进、后退和转向；目标超出范围停车 |
| 雷达警卫 | 检测区最近目标距离 **<检测距离** 时响应 | 只原地转向朝向目标，不前进或后退；不是报警器或自动巡逻 |

跟随、警卫识别的是最近雷达回波，不能识别人或指定物体。跟随的距离 PID 以检测距离一半为控制目标；源码同时保留了以 **0.20 m** 为中心、约 **±0.02 m** 的固定前后死区。两者并不完全一致，本次按原厂实现迁移，没有另改公式。跟随/警卫与避障是互斥模式，不叠加运行。

### 厂家算法保真与电脑端保护

避障转弯时前进速度为用户速度的 **1/6**、角速度幅值为速度的 **6 倍**；转向符号和保持时间按原厂状态机计算。保持期间继续发送上次有效速度指令，等原厂计时结束再根据新扫描决定方向；不采用之前自研的逐帧轨迹避障或换向策略。

跟随/警卫保留厂家 PID 参数、5° 转向死区、0.08 rad/s 转向输出死区，跟随另外保留 0.01 m/s 前进输出死区。标准型号和 G4 数组切片、G4 的转向符号与限幅分支均迁入。`scan_angle`、`lidar_type` 可在配置中设置，普通型号使用 `standard`，G4 使用 `G4`。

扫描时间戳重复不会刷新接收时间。运行中扫描超过 0.55 秒未更新时，不再取消巡航，而是保持会话与录像、持续发送零速并显示“等待新数据后自动继续”。收到新的有效扫描后，重新初始化本轮转弯/PID状态并自动继续，避免延续中断前的旧动作。启动新的巡航仍要求雷达与画面就绪。消息格式/坐标系错误、检测区有效点不足、接收时间无效、连接或发送失败仍归零并取消；手动停止后不会自动恢复。

PID 每个新雷达帧只更新一次，界面重复刷新不会重复计算。JSON null、非有限值、零、负数和超量程数据不会当成空地；无数据时也不会沿用旧非零命令。未导入 ROS 节点或调用厂家 enter/exit 服务，因此不会发送厂家初始化舵机姿态。

### 设置、记录与验证

`app/config/settings.json` 的 `cruise` 保存 `detection_distance`、`speed`、`mode`、`scan_angle`、`lidar_type`。旧前后距离迁为检测距离，原值在新厂家范围之外时裁到 0.30–1.50 m，旧左右距离移除；已有单距离优先。有效速度及其它功能、逐车夹取标定保留。选择上次模式不会自动让车运动。

每次启动仍自动将视频、关键帧和 JSON 直接保存在电脑 `app/捕获/自动巡航/<时间>/`。记录包含 `algorithm=vendor_lidar_controller`、模式、实际参数、原始扫描和同帧决策。正在录像时换模式会结束旧会话，避免两种模式混在同一份记录中。

旧算法的实现、配置和测试已备份到 `.work/vendor_cruise_migration/20261025_162429/backup/` 后移除；旧实车录像继续保留，但不能作为新算法的实车验证。本次没有连接或驱动车辆，也没有修改车内文件、服务、网络或舵机。

本版通过 113 项自动测试：112 通过，1 项 Linux 专用检查跳过。包含直接执行厂家原始回调与 PID 的参考对照，覆盖 1800 帧确定性状态序列、三种模式、两种雷达分支、死区、定时保持、配置迁移、换模式停车、录像归属和其他页面回归。三种新模式尚未实车验证，重启电脑 App 后加载。

## 沙盘建模 + 实时展示

本页通过 SSH 在车端 ClawPi 容器中运行已有的 ROS 2 Humble `slam_toolbox`，直接使用厂家 `slam/config/slam.yaml`，订阅 `/scan_raw` 并复用现有里程计和 TF。摄像头在第一版中用于实时观察，不参与 SLAM 融合，生成的是二维占用地图，不是建筑纹理或三维重建。

1. 在顶部选好车辆，等待 ROS 和摄像头连接；进入本页，点击“连接 / 检查”。凭据沿用本机已有资料，也可在页面填写；密码不保存到配置或日志。
2. 点击“开始建图”。程序只启建图节点，避免重新启动底盘、雷达和摄像头；若已有 `/slam_toolbox`，则接入已有建图。地图、定位、雷达和画面就绪后可低速遥控。默认 0.04 m/s，可设 0.02–0.10 m/s。
3. 鼠标按住方向按钮，松开或移出即停；键盘模式需点击启用，并保持控制区焦点。W/S 前后、A/D 转向、Q/E 平移，空格/Esc 停止。本页按住持续移动，无固定行驶时长限制。切页、失焦、连接或关键传感器数据失效时停止遥控；SLAM 可在切页后继续建图。
4. 左侧显示地图、车辆位置朝向和轨迹，支持缩放、拖动、适配；右侧沿用共享摄像头，两个区域可拖动中线调整宽度。
5. 完成后先点击“保存到小车和电脑”，再点击“结束建图”。小车目录可在“ClawPi 容器”或“小车宿主机”中明确选择；默认容器 `/home/ubuntu/ros2_ws/src/slam/maps`。必须选择已有目录，程序在其中新建唯一地图子目录，不覆盖旧地图。

电脑端固定根目录是 `app/savedMap`，与启动时的工作目录无关。每次保存产生独立的 `<地图名>_<时间>_<唯一编号>` 文件夹，包含 `map.pgm`、`map.yaml` 和本机 `manifest.json`；序列化服务可用时还包含供后续继续建图使用的 `map.posegraph` 与 `map.data`。本页保存继续建图状态，但第一版不提供加载状态继续建图的按钮。

地图先在车端保存，再下载并逐文件检查大小与 SHA256，完成后才发布到本地正式目录；YAML 使用相对图像路径，便于搬移。选择宿主机目录时，明确经过容器到宿主机的复制校验，成功后精确清理容器临时副本。下载失败会报告已保存的车端目录；序列化失败会提示二维地图已保存但继续建图状态缺失，不会声称全部完成。
