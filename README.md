> **视觉追踪夹取已完成本车实测（2026-10-23）**：2 号车红色目标已保存有效近端标定。以后把同一目标放远、保持视野内，点击“一键追踪夹取”即可；不要把远处目标重新标定为可夹位置。软件会自动对准、慢速接近、停车合爪并抬升。本次里程计累计接近 21.2 cm，用户现场确认已夹住并离地。

# 小车控制台（ClawPi Console）

本说明位于项目根目录。桌面程序在 `app/`，独立摄像头预览工具在根目录的 `tools/`。
下文未带 `app/` 前缀的配置和源码路径均相对于 `app/` 目录，Python 模块命令也请在该目录运行。

一个基础控制使用标准库、视觉追踪需要 **Pillow**、集成终端需要 **Paramiko＋pyte**、可整包拷贝给别人的桌面小程序，用来通过网线直连操控这台树莓派小车：
看实时画面、控制夹爪与云台、随时掌握小车状态。

- 语言 / 界面：Python 3.8+ 标准库 + Tkinter
- 通信方式：HTTP（图像流）+ WebSocket（ROS 指令与状态）
- 基础夹取/视频不需要 OpenCV 或本机 ROS；集成终端另需 Paramiko、pyte 和小车 SSH 账号
- 夹取/视频不部署车内程序；文件浏览区只读。集成终端按你输入的 Linux 命令执行，效果与 SSH 登录后相同。

## 一、怎么启动

### 1. 先给电脑配好网段（只做一次）

小车自己的地址是 `192.168.150.3`，电脑的以太网口必须在同一网段。

**方式 A（推荐，双击就行）**

以管理员身份运行：

```
app\tools\设置本机网卡IP.bat
```

按提示选网卡名、填 IP（默认 `192.168.150.100`），脚本会调用 `netsh` 设好。

**方式 B（手动）**

`控制面板 → 网络和共享中心 → 更改适配器设置 → 右键"以太网" → 属性 → IPv4`：

| 项 | 填什么 |
|---|---|
| IP 地址 | 192.168.150.100 |
| 子网掩码 | 255.255.255.0 |
| 默认网关 | 留空 |
| DNS | 留空 |

> 为什么不用 DHCP：小车的网口是静态地址，路由器不一定给它发 IP，直接静态配最省事。

### 2. 用网线连接

网线一头插小车网口，一头插电脑网口。小车开机约 40~60 秒后 ROS 环境起来。

验证一下：

```bash
ping 192.168.150.3
```

### 3. 双击启动

```
app\run.bat
```

程序会自动连接 `config/settings.json` 里配置的小车地址；连不上就点顶部「**自动搜索**」，
它会依次扫 `192.168.150.0/24`（网线）和 `192.168.149.0/24`（小车 WiFi 热点）两段，
找到同时开着 8080 与 9090 的那台机器（约 2 秒）。

macOS / Linux 用 `./run.sh`。

**命令行参数**（可选，一般用不到）

```bash
python -m carapp.main --host 192.168.150.3     # 临时改小车地址，不改配置文件
python -m carapp.main --tab gripper            # 启动直接落在"夹取"页
python -m carapp.main --tab remote             # 启动直接落在"远程遥控"页
```

### 4. 不用网线：连小车自己发的 WiFi 热点

小车（树莓派 5 的 `wlan0`）本身就是一个 **AP 热点**，和网口是两条并行的接入路径，
两条可以同时用，功能完全一样（8080 与 9090 都监听在 `0.0.0.0`，从哪个口进来都通）。

| 项 | 值 |
|---|---|
| SSID | **HW-10CCA58E** |
| 密码 | `hiwonder` |
| 频段 | 5 GHz，信道 36（**2.4G-only 的老网卡扫不到**） |
| 小车地址 | `192.168.149.1` |
| 客户端地址 | 由小车 DHCP 自动分配（`192.168.149.10 ~ 254`） |

所以走 WiFi 时 **不需要手动配 IP**，连上就有地址，然后：

```bash
python -m carapp.main --host 192.168.149.1
```

推荐先在 Windows 连接对应车辆的热点，再在 App 顶部选择车辆，连接方式选「Wi-Fi 热点」。
App 会核对热点 SSID；未识别或与所选车不一致时，日志会提示正确的热点名称并持续等待。
两台车的热点 IP 都是 `192.168.149.1`，不能单靠这个 IP 判断是哪一台。

两条路的取舍：

| | 网线 | WiFi 热点 |
|---|---|---|
| 要不要配 IP | **要**（192.168.150.x + 掩码 255.255.255.0） | 不要，DHCP 自动 |
| 延迟 / 稳定性 | 更好 | 略差，5G 距离短 |
| 上网 | 不影响（另插一路也行） | 连上后**上不了互联网**，除非电脑还有第二块网卡 |

> 注意：网线那套 IP 配置（`192.168.150.109`）**不是可选项**。小车网口是静态地址
> `192.168.150.3`，电脑必须在同一网段才通；不配就相当于两台机器没接在同一张网上。
> WiFi 之所以免配置，是因为小车在这条路上当了 DHCP 服务器。

### 5. 有两台车怎么用

顶部选择「车辆」和「有线网口 / Wi-Fi 热点」，选中后重连并记住选择。

| 车辆 | 有线固定地址 | Wi-Fi 热点名 | 热点地址 |
|---|---|---|---|
| 1 号车 HW-10CCA58E | `192.168.150.3` | `HW-10CCA58E` | `192.168.149.1` |
| 2 号车 HW-A0857935 | `192.168.150.2` | `HW-A0857935` | `192.168.149.1` |

上述有线地址来自两车采集文档中的 NetworkManager 持久配置。这两台车无需再次改 IP。
旧资料里的 `sudo ip addr add ...` 只添加临时地址，重启即失效，不能据此判断固定地址。

有线连接：接好网线，将电脑**对应的有线网卡**设为 `192.168.150.100`，掩码 `255.255.255.0`，
网关留空，再在顶部选车。若没有以太网网卡或目标网段地址，自动搜索也无法代替物理连接和网卡配置。
两台同时经交换机连接时，按上表选车；App 每次控制其中一台。

Wi-Fi 连接：先在系统连上目标车辆的热点，再在 App 选该车和「Wi-Fi 热点」。
App 读取 SSID，只有与所选车辆一致才建立连接；电脑只能连一个热点。Windows 通过 `netsh` 读取，
Linux 需提供 `iwgetid`；系统无法读取 SSID 时使用有线连接或先解决系统权限/工具问题。

车辆刚开机通常需要约 40–60 秒启动服务。ROS 与摄像头各自持续重试当前地址，断电、拔线后恢复网络
会重新连接；ROS 心跳检测失活连接。断线会取消动作，重新连接后由操作者重新发起动作。
不会因为另一台车在线就自动切换。自动搜索仅列出有图像或 ROS 端口响应的候选，需手动选地址。

「连接诊断」会显示本机网卡地址、目标地址、Wi-Fi SSID 和两个服务端口是否可达，
用于区分网段不对、热点选错、业务服务还没启动。诊断不会修改电脑或车辆配置。

两车热点下的视觉夹取标定分别保存。旧的有线标定可读取，但必须通过新版近端位置和版本校验；原来仅以热点 IP 保存的标定无法区分车辆，
需要对两台车重新单独标定。车辆身份与网络适配并不代表相机方向和夹取位置已完成逐车实测校准。

## 三、一个页面，两块内容

### 1. 车轮（配合夹取对位）

> 以前只能动夹子，方块偏一点就夹空。现在可以让车自己往前挪一点。

| 操作 | 说明 |
|---|---|
| 速度档 | 慢 0.06 / 中 0.10 / 快 0.15 m/s，默认**慢**（对位够用，撞到东西也不狠） |
| ↑↓←→ | **按住走、松开停**，转角速度 0.40 rad/s |
| ■ 停止 | 立刻归零（连发 3 次零速，防止控制器那边漏收） |
| 点动 前/后 0.3s | 走固定时长自动停，用来一格一格挪 |

安全阀：单次按住最长 **5 秒**，超时会自己停车并在日志里提示；关窗口、切走动作时也会归零。
速度、单次时长都在 `config/settings.json` 的 `base` 段里改。

### 2. 夹取

**快捷动作**（只动你点的那个关节，其他不动）

| 按钮 | 作用 | PWM |
|---|---|---|
| 张开夹爪 | 两指张开 | 2000 |
| 闭合夹爪 | 两指合上 | 1500 |
| 半开夹爪 | 中间开度，不代表夹持力 | 1750 |
| 升降臂抬起 / 降下 | 用户实机确认方向，按钮与序列共用配置 | 1200 / 1700 |
| 云台俯视 / 前视 | 俯视夹取区 / 看前方（2 号车实测） | 1300 / 1500 |

> 当前 2 号车按 2026-10-23 稳定图像校准：1300 俯视夹取区、1500 前视。旧方向记录已被本次证据覆盖；1 号车需独立核对。

**预设姿态**：一键把 4 个关节同时设到某个组合（值在 `config/settings.json` 的 `servo.presets` 里改）

**一键夹取（车轮配合）**：
`张爪 → 降臂 → 前进 N 秒 → 合爪 → 抬臂 → 后退 M 秒`。
N/M 就在按钮左边的输入框里改（默认 0.6 / 0.4 秒，按慢档算是 3.6 cm / 2.4 cm）。
中途点「中止」会立刻停车并停在这一步。

它只保证"动作与位移都下发了"，不判断有没有真夹到（看到夹爪动作仍不等于检测到抓取成功）。

**滑杆**：四路舵机各一条，拖动后点「应用全部」，参数边界来自 `servo.limits`

### 3. 实时画面

画面不再是独立选项卡，就在这一页最下面，夹的时候一直能看到。

- **图像话题**：默认 `/image_raw`（原始画面）。下拉可切到算法调试图：
  - `/color_track_pick/image_result` 颜色抓取识别结果
  - `/line_following/image_result` 图像循线结果
  - `/object_tracking/image_result` 目标跟踪结果
  - `/llm_control/image_result` 大模型控制结果
- **自适应缩放**：窗口越小画面越小（只缩不放），不会把窗口撑变形
- **抓帧**：把当前帧存成 jpg/png，落在 `app/捕获/`，文件名带时间戳
- **开始录制**：录的是**你电脑上的文件**，不是车上的
  - JPEG 模式 → 存成 `.mjpg`，VLC / PotPlayer 可直接播放
  - PNG 模式 → 逐帧存到 `app/捕获/预览录像/帧序列_*/` 文件夹

## 五、怎么加一个新功能

以"加一个「里程计」选项卡"为例，三步：

**第 1 步**：新建 `carapp/features/odom.py`

```python
import tkinter as tk
from carapp.features.base import Feature
from carapp.ui import theme

class OdomFeature(Feature):
    key = "odom"
    title = "里程计"

    def build(self, parent):
        self.lbl = tk.Label(parent, text="--", bg=theme.BG, fg=theme.TEXT)
        self.lbl.pack(padx=12, pady=12, anchor="w")

    def on_tick(self, st):
        pose = st.get("pose")
        if pose:
            self.lbl.config(text="x=%.3f  y=%.3f  yaw=%.1f°" % pose)
```

**第 2 步**：在 `carapp/features/__init__.py` 里注册

```python
from carapp.features.odom import OdomFeature

FEATURES = [
    CameraFeature,
    GripperFeature,
    OdomFeature,      # ← 新增
]
```

**第 3 步**：重启程序。选项卡自动出现，`main.py` 不用改。

### AppContext 能给你什么

`self.ctx` 是所有公共能力的入口：

| 用法 | 作用 |
|---|---|
| `self.ctx.state` | 读全局状态（位姿、电压、节点数、帧率…） |
| `self.ctx.bridge.publish(topic, msg)` | 发布任意 ROS 话题 |
| `self.ctx.bridge.subscribe(topic, throttle_ms)` | 订阅任意话题（消息会进 `state`，需要自定义解析就在 `main.py` 的 `_on_ros_message` 加分支） |
| `self.ctx.bridge.call_service(srv, args, cb)` | 调 ROS 服务 |
| `self.ctx.publish_servo({"gripper":1500}, duration=0.8)` | 舵机指令的快捷方式 |
| `self.ctx.add_frame_listener(cb)` | 注册摄像头帧回调 `cb(ts, payload, mode)` |
| `self.ctx.save_dir()` | 拿到 `app/捕获/` 的绝对路径（自动创建） |
| `self.ctx.log("...")` | 往底部日志写一行 |

## 六、通信协议（排错时有用）

程序不碰 SSH，全部走车上已经跑着的两个服务：

| 端口 | 服务 | 用途 | 举例 |
|---|---|---|---|
| 8080 | `web_video_server` | 图像流 | `http://192.168.150.3:8080/stream?topic=/image_raw&type=mjpeg` |
| 9090 | `rosbridge_websocket` | 指令与状态 | `ws://192.168.150.3:9090` |

**控制夹爪实际发的消息**：

```json
{
  "op": "publish",
  "topic": "/ros_robot_controller/pwm_servo/set_state",
  "msg": {
    "duration": 0.8,
    "state": [{ "id": [4], "position": [1500], "offset": [0] }]
  }
}
```

**控制车轮实际发的消息**（车上的 `controller` 节点在订这条话题，和手柄/APP 同一条通路）：

```json
{
  "op": "publish",
  "topic": "/controller/cmd_vel",
  "msg": {
    "linear":  { "x": 0.06, "y": 0.0, "z": 0.0 },
    "angular": { "x": 0.0, "y": 0.0, "z": 0.0 }
  }
}
```

停车就是连发 3 次全 0（怕丢包，也怕控制器那边超时判定不一致）。
实测验证：发一条后，在车上 `ros2 topic echo /controller/cmd_vel` 能原样收到，说明话题名与消息结构都对。

**舵机 ID 对应关系**（改 `config/settings.json` 可调）：

| ID | 关节 | 范围 | 备注 |
|---|---|---|---|
| 1 | 云台俯仰 | 1150–2250 | 物理 1000–2400，两端各留 150；2 号车俯视 1300 / 前视 1500 |
| 2 | 云台水平 | 650–2350 | 物理 500–2500，两端各留 150 |
| 3 | 升降臂 | 1200–2000 | 1200 是硬件下限 |
| 4 | 夹爪 | 1500–2000 | 2000 张开 / 1500 闭合 / 1750 半开 |

## 七、常见问题

| 现象 | 原因与处理 |
|---|---|
| 顶部一直「● 重连中」，画面也黑 | 点「连接诊断」，检查目标车辆、电脑是否有 192.168.150.x 的有线地址，或是否连上该车的 Wi-Fi 热点 |
| 能 ping 通但连不上 | 车上服务可能还没起来。开机后通常等 40–60 秒，App 会持续重试；诊断里的 8080 / 9090 可分别检查服务是否监听 |
| 换车后连不上 | 选对应的车及连接方式；有线 1 号 .3、2 号 .2；Wi-Fi 要先换系统连接的热点，不能只改 App 里的 IP |
| 重启后 ROS 恢复但画面不恢复 | 新版摄像头已加入断流/启动失败重试；确认选的是有图像的话题，日志应显示重新拉流 |
| 画面有但很卡 | PNG 模式带宽约 20 Mbps、JPEG 约 5 Mbps。装个 Pillow 就会自动切到 JPEG 模式（见下） |
| 夹爪点了没反应 | 看日志有没有「下发失败：ROS 未连接」；再确认 `/ros_robot_controller` 节点在（顶部节点数应为 33） |
| 双击 run.bat 一闪而过 | 没装 Python，或安装时没勾 "Add Python to PATH" |
| 中文变乱码 | 用 `run.bat` 启动（它已执行 `chcp 65001`），别用系统默认终端 |

**关于 Pillow（可选）**

装了会自动切换到 JPEG 模式：画质更好、带宽只有 1/4、帧率更高。不装也能用（PNG 模式）。

```bash
pip install Pillow
```

**双击 `run.bat` 后满屏「不是内部或外部命令」「乱码」**

这是批处理文件的**编码/换行**问题，不是程序问题。cmd 只认 GBK + CRLF 的 `.bat`；
如果被编辑器存成 UTF-8 或 LF 换行，就会出现 `'PYEXE' 不是内部或外部命令`、
`'"RUN=py -3"' 不是内部或外部命令` 这类错。

仓库里的 `run.bat` 已经是 GBK + CRLF，正常不会有这个现象。万一你用 VS Code
之类的编辑器改过它并保存，请按下图恢复：右下角编码选 **GB2312/GBK**，
换行符选 **CRLF**，或者直接重新拷贝一份原始文件。

（`run.sh` 只给 macOS/Linux 用，保持 UTF-8 + LF，两者不要混。）

**关于「夹爪看不到」**

2 号车本次画面能够看到夹爪。是否能看清取决于云台角度和车辆装配；程序尚未实现抓取成功检测，仍需人工观察或独立传感器确认。

## 八、移植到别的电脑要改什么

一般**什么都不用改**：

1. 整个 `app/` 文件夹拷过去
2. 装 Python 3.8+（勾 PATH）
3. 配好本机网段（`tools\设置本机网卡IP.bat`）
4. 双击 `run.bat`

只有两种情况需要动 `config/settings.json`：

- 小车 IP 不是 `192.168.150.3` → 改 `car.host`（或程序里点「自动搜索」）
- 有第二台车 → 改 `cars` 列表（见第一节第 5 小节）
- 小车不在 150 网段 → 改 `car.subnet_prefixes`（默认已含 `192.168.150` 与 `192.168.149` 两段），
  否则自动搜索扫错网段

## 九、已知限制

- 舵机**没有位置回读**：车上那个 `pwm_servo/get_state` 服务实现有 bug，一调就把控制器节点搞崩，
  所以顶部「夹爪目标」显示的是**最后下发的指令值**，不是实测角度
- 图像约 7~10 fps：相机配置写着 30 fps 但实际跑不到，瓶颈在 YUV 转换与 ROS 传输
- **没有里程计闭环**：车轮是"按时间推"的开环控制，走 0.6 秒约 3.6 cm 只是估算，
  地面打滑、电量、轮子摩擦都会让实际距离有偏差。要精确对位就用「点动 0.3s」一点点蹭，
  或者看画面自己按
- **未实现抓取成功检测**：2 号车可看到夹爪，但程序尚未自动判断是否夹住目标。


## 视觉追踪夹取（颜色目标）

当前支持红/绿/蓝/黄色显著目标；在视野内的单个目标上工作，不进行路径绕障或视野外搜索。追踪需要 Pillow；已有手动、定时控制可继续使用。

首次使用某辆车、某种颜色或更换目标尺寸、相机姿态时：

1. 选择颜色，点击“①视觉准备”，等舵机稳定。
2. **把目标放到张开的两爪之间，确认闭合便能夹住**，再点击“②两爪间标定”。不能用远处目标标定；固定准备姿态下，画面上半部分的目标将被拒绝。
3. 将同一目标移远，保持目标在视野内、接近路线通畅，点击“一键追踪夹取”。
4. APP 持续对准并接近，目标回到标定位置且连续多帧稳定后才停车、合爪和抬升。中途可点“中止追踪”或全局停止。

**当前 2 号车红色目标无需重新标定**，已由用户放在两爪之间采样：参考中心 x≈0.451、y≈0.762、宽度≈0.259；准备姿态 CH1=1300、CH2=1500、CH3=1700。

自动接近默认最大线速度 0.06 m/s、单次最大里程计累计距离 0.8 m、最长 45 秒。丢失目标、过期图像、过期里程计、超时或超过行程都会停止；这不等于断电级急停。

运行视频、关键帧、阶段与速度/位姿记录保存在电脑 `app/捕获/追踪夹取/时间戳/`。原按固定时长前后移动的功能保留为“定时夹取（原模式）”。动作执行完毕不代表程序自动识别了抓取成功，仍需现场或图像确认。

测试：在 app 目录运行 `python -m unittest discover -s tests -v`。


## 集成终端

上方“集成终端”选项卡分左右两栏，可拖动中间分隔条调整宽度。

- **左侧 SSH 交互终端**：连接顶部所选车辆，运行小车上的 Linux Shell。支持持续会话、`cd`、方向键历史、Tab 补全、Ctrl+C 中断、Ctrl+Shift+C/V 复制粘贴、中文及终端光标控制。它不是电脑本机的 PowerShell。
- **右侧文件浏览器**：可切换“宿主机”和“ClawPi 容器”，进入目录、返回上级、地址栏跳转、刷新、复制路径和只读预览文件。点击“ROS 源码”直接打开容器 `/home/ubuntu/ros2_ws/src`。文件列表显示名称、大小和车端修改时间；车端时间未同步时修改时间可能不准确。
- 双击目录进入，双击普通文本文件预览；预览最多 256 KB，二进制文件只显示提示。文件读取不依赖 SFTP，因此不需要为 1 号车修改 SSH 服务。
- 文件浏览视图与左侧 Shell 当前目录独立。左侧“进入 ClawPi”按钮在宿主机命令提示符下使用，进入容器并加载 ROS 2 环境。若已经进入容器，先 `exit` 回到宿主机再用该按钮。

### 启动和登录

在电脑的 app 目录安装依赖：

```bash
python -m pip install -r requirements.txt
```

当前电脑已经安装。APP 基础功能在没有终端依赖时仍可启动；终端页会提示缺少依赖。

1. 顶部选择正确车辆及连接方式，打开“集成终端”。
2. 输入用户名与密码，点击“连接 SSH”。用户名默认 pi，端口默认 22（配置项 `terminal.port`）。
3. 若项目根目录已有用户提供的“小车账号密码信息.txt”，密码会预填到内存并以掩码显示；首次进入终端页自动连接。密码不写入 settings.json，也不会写入日志。复制 app 到别的电脑且没有该文件时，手动填写密码即可。
4. 切换车辆会关闭旧 SSH 会话和文件列表，之后点击“连接 SSH”，不会重放上台车输入的命令。SSH 与 ROS/视频连接相互独立。

SSH 主机公钥指纹保存在电脑 `app/config/ssh_known_hosts`；同热点 IP 的两台车按车辆档案分别记录。首次连接记录指纹，之后若主机密钥变化会拒绝连接。

在 app 目录可直接选中新页启动：

```bash
python -m carapp.main --tab terminal
```

新增模块：`core/ssh_session.py`（SSH、独立文件读取）、`core/terminal_buffer.py`（VT100 显示）、`features/terminal.py`（左右界面）。


## 远程遥控 + 实时画面（2026-10-23）

上方第二个选项卡提供鼠标／键盘两种操控模式，下方显示当前车辆实时画面，可抓帧或录制到电脑。夹取页也新增了“平移左转”“平移右转”，这两个操作是麦轮横向平移，不改变车头朝向。

鼠标模式：按住车轮或云台按钮持续动作，松开或移出按钮停止；抬臂、降臂、张爪、合爪单击执行一次。使用顶部速度下拉选择慢／中／快，默认慢速。

键盘模式：先选择“键盘操控”，再点击“点击启用键盘操控”，保持按键说明区域获得焦点（蓝色边框）。建议使用英文输入状态。点击其他输入框会退出键盘操控，集成终端的输入不会操纵小车。

| 功能 | 按键 | 行为 |
|---|---|---|
| 前进 / 后退 | W / S | 按住移动，松开停止 |
| 原地左转 / 右转 | A / D | 按住旋转，松开停止 |
| 平移左转 / 平移右转 | Q / E | 按住横移，松开停止 |
| 云台仰视 / 俯视 | I / K | 按住微调，每步 PWM 40 |
| 云台水平左转 / 右转 | J / L | 按住微调，每步 PWM 40 |
| 升降臂抬起 / 降下 | T / G | 1200 / 1700，按下一次执行一次 |
| 张开 / 闭合夹爪 | F / H | 2000 / 1500，按下一次执行一次 |
| 停止并退出键盘操控 | 空格 / Esc | 停止底盘和云台重复指令 |

键盘支持多键组合，前进＋横移的合速度不超过所选速度；相反方向按键抵消。底盘和云台连续按住最多 5 秒，到时停止，松开后重新按下可继续；操作系统的自动重复按键不会延长计时。

切换模式、离开控制页、窗口失焦或换车会取消动作并发送零速；恢复连接先发送零速，不自动恢复之前的动作。离开夹取页会中止追踪夹取或定时序列。已经下发的舵机目标可能继续完成本次动作。

云台使用既有安全范围 CH1 1150–2250、CH2 650–2350；首次没有已知目标时，以俯视 1300／水平居中 1500 为参考，不是实际位置回读。2 号车验证为 CH1 增大向上、CH2 增大向左；另一台车的实际安装方向需单独核对。

遥控功能不安装新依赖，不改写车辆文件。录像和抓帧仍保存在电脑 `app/捕获/`；本次验证材料位于 `.work/remote_control/20261023_193202/`。
