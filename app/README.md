> **本次实测覆盖旧方向记录**：2026-10-23 在 2 号车连续稳定取帧，1150 朝向车体下方，1300 俯视夹取区，1500 看前方。现按钮采用俯视 1300 / 前视 1500。旧文中“数值越大越朝下”不适用于当前 2 号车；1 号车需单独校准。

> **2026-10-23 参数校准**：以用户最新物理范围为准。CH1 1000–2400、CH2 500–2500，相机两端各留 150，APP 实际范围为 **1150–2250 / 650–2350**；CH3 **1200–2000**；CH4 **1500–2000**。张爪 2000、闭合 1500、半开 1750。原“夹紧 1800”改为半开，避免把位置值误称为夹持力。前视改为 1500、俯视改为 1300（本次 2 号车验证），不再使用物理边界 1000。全部按钮、滑杆、预设、序列均经过发送前限位校验；越界请求整条拒绝。配置文件和默认配置均已同步。

# 小车控制台（ClawPi Console）

一个**零第三方依赖**、可整包拷贝给别人的桌面小程序，用来通过网线直连操控这台树莓派小车：
看实时画面、控制夹爪与云台、随时掌握小车状态。

- 语言 / 界面：Python 3.8+ 标准库 + Tkinter
- 通信方式：HTTP（图像流）+ WebSocket（ROS 指令与状态）
- 不依赖：不需要 opencv、不需要 paramiko、不需要装 ROS、不需要 SSH 密码
- 车内零写入：程序只读画面、只发指令，**不会在小车上生成任何文件**

---

## 一、怎么启动

### 1. 先给电脑配好网段（只做一次）

小车自己的地址是 `192.168.150.3`，电脑的以太网口必须在同一网段。

**方式 A（推荐，双击就行）**

以管理员身份运行：

```
tools\设置本机网卡IP.bat
```

按提示选网卡名、填 IP（默认 `192.168.150.100`），脚本会调用 `netsh` 设好。

**方式 B（手动）**

`控制面板 → 网络和共享中心 → 更改适配器设置 → 右键"以太网" → 属性 → IPv4`：

| 项 | 填什么 |
|---|---|
| IP 地址 | 192.168.150.100 |
| 子网掩码 | 255.255.255.0 |
| 默认网关 | 留空 |
| DNS | 留空 |

> 为什么不用 DHCP：小车的网口是静态地址，路由器不一定给它发 IP，直接静态配最省事。

### 2. 用网线连接

网线一头插小车网口，一头插电脑网口。小车开机约 40~60 秒后 ROS 环境起来。

验证一下：

```bash
ping 192.168.150.3
```

### 3. 双击启动

```
run.bat
```

程序会自动连接 `config/settings.json` 里配置的小车地址；连不上就点顶部「**自动搜索**」，
它会依次扫 `192.168.150.0/24`（网线）和 `192.168.149.0/24`（小车 WiFi 热点）两段，
找到同时开着 8080 与 9090 的那台机器（约 2 秒）。

macOS / Linux 用 `./run.sh`。

**命令行参数**（可选，一般用不到）

```bash
python -m carapp.main --host 192.168.150.3     # 临时改小车地址，不改配置文件
python -m carapp.main --tab gripper            # 启动直接落在"夹取"页
```

### 4. 不用网线：连小车自己发的 WiFi 热点

小车（树莓派 5 的 `wlan0`）本身就是一个 **AP 热点**，和网口是两条并行的接入路径，
两条可以同时用，功能完全一样（8080 与 9090 都监听在 `0.0.0.0`，从哪个口进来都通）。

| 项 | 值 |
|---|---|
| SSID | **HW-10CCA58E** |
| 密码 | `hiwonder` |
| 频段 | 5 GHz，信道 36（**2.4G-only 的老网卡扫不到**） |
| 小车地址 | `192.168.149.1` |
| 客户端地址 | 由小车 DHCP 自动分配（`192.168.149.10 ~ 254`） |

所以走 WiFi 时 **不需要手动配 IP**，连上就有地址，然后：

```bash
python -m carapp.main --host 192.168.149.1
```

或者直接点「自动搜索」，它会自己找到。想长期生效就改 `config/settings.json` 里的
`car.host` 为 `192.168.149.1`。

两条路的取舍：

| | 网线 | WiFi 热点 |
|---|---|---|
| 要不要配 IP | **要**（192.168.150.x + 掩码 255.255.255.0） | 不要，DHCP 自动 |
| 延迟 / 稳定性 | 更好 | 略差，5G 距离短 |
| 上网 | 不影响（另插一路也行） | 连上后**上不了互联网**，除非电脑还有第二块网卡 |

> 注意：网线那套 IP 配置（`192.168.150.109`）**不是可选项**。小车网口是静态地址
> `192.168.150.3`，电脑必须在同一网段才通；不配就相当于两台机器没接在同一张网上。
> WiFi 之所以免配置，是因为小车在这条路上当了 DHCP 服务器。

### 5. 有两台车怎么用

顶部最左边是**车切换下拉**，配置文件 `cars` 里有几项就列几项，选中即重连（会记住上次用的那台）。

```json
"cars": [
  { "name": "1 号车", "host": "192.168.150.3" },
  { "name": "2 号车", "host": "192.168.150.2" }
]
```

> 本项目实测的两台车**出厂地址就不一样**：1 号车 `192.168.150.3`、2 号车 `192.168.150.2`
> （NM 里都是 `manual` 静态），所以同时插网线不冲突。
> 如果你的两台车都是 `192.168.150.3`，按下面表格第二种用法改一台。

**关键前提：如果两台车出厂地址相同（都是 `192.168.150.3`），同时插网线会 IP 冲突**，表现是
"能 ping 通但时连时断、状态乱跳"。所以有两种用法：

| 用法 | 做法 | 适合 |
|---|---|---|
| **一次只插一台**（省事） | 想用哪台就插哪台的线，点「自动搜索」即可 | 单人轮流调试 |
| **两台同时在线**（推荐） | 给第二台改静态地址，例如 `.4` | 要对比、要同时开着 |

给第二台改地址的步骤（**一定要走 WiFi 进去改，别用网线进**，否则改完自己就被踢下来了）：

```bash
# 1) 电脑先连第二台车的热点（SSID 形如 HW-xxxxxxxx，密码 hiwonder）
ssh pi@192.168.149.1          # 密码 raspberrypi

# 2) 改它的网口地址（把 .4 换成你要的）
sudo nmcli connection modify eth0 ipv4.addresses 192.168.150.4/24
sudo nmcli connection up eth0

# 3) 验证
ip -br addr show eth0         # 应显示 192.168.150.4/24
```

改完之后，在 `config/settings.json` 的 `cars` 里把第二项的 `host` 填成 `192.168.150.4`，
之后下拉就能一键切换了。

> 「自动搜索」如果同时扫到多台，会弹窗列出来让你选，不会瞎猜一台连上去。
>
> **启动兜底**：程序启动 5 秒还没连上，会自动扫一遍网段——只找到一台就直接切过去并写进日志。
> 两台车换着用时，忘了改下拉也不会一直「未连接」（搜到多台时仍会让你手动选）。
>
> 走 **WiFi** 时两台车的热点地址都是 `192.168.149.1`，只能靠 SSID（`HW-xxxxxxxx`）区分，
> 而电脑的无线网卡一次只能连一个热点 —— 所以 WiFi 路上天然"一次一台"。

## 三、一个页面，两块内容

### 1. 车轮（配合夹取对位）

> 以前只能动夹子，方块偏一点就夹空。现在可以让车自己往前挪一点。

| 操作 | 说明 |
|---|---|
| 速度档 | 慢 0.06 / 中 0.10 / 快 0.15 m/s，默认**慢**（对位够用，撞到东西也不狠） |
| ↑↓←→ | **按住走、松开停**，转角速度 0.40 rad/s |
| ■ 停止 | 立刻归零（连发 3 次零速，防止控制器那边漏收） |
| 点动 前/后 0.3s | 走固定时长自动停，用来一格一格挪 |

安全阀：单次按住最长 **5 秒**，超时会自己停车并在日志里提示；关窗口、切走动作时也会归零。
速度、单次时长都在 `config/settings.json` 的 `base` 段里改。

### 2. 夹取

**快捷动作**（只动你点的那个关节，其他不动）

| 按钮 | 作用 | PWM |
|---|---|---|
| 张开夹爪 | 两指张开 | 2000 |
| 闭合夹爪 | 两指合上 | 1500 |
| 半开夹爪 | 中间开度，不代表夹持力 | 1750 |
| 升降臂抬起 / 降下 | 抬起≈举高，降下=贴地 | 1700 / 1200 |
| 云台俯视 / 前视 | 俯视夹取区 / 看前方（2 号车实测） | 1300 / 1500 |

> 当前 2 号车按 2026-10-23 稳定图像校准：1300 俯视夹取区、1500 前视。旧方向记录已被本次证据覆盖；1 号车需独立核对。

**预设姿态**：一键把 4 个关节同时设到某个组合（值在 `config/settings.json` 的 `servo.presets` 里改）

**一键夹取（车轮配合）**：
`张爪 → 降臂 → 前进 N 秒 → 合爪 → 抬臂 → 后退 M 秒`。
N/M 就在按钮左边的输入框里改（默认 0.6 / 0.4 秒，按慢档算是 3.6 cm / 2.4 cm）。
中途点「中止」会立刻停车并停在这一步。

它只保证"动作与位移都下发了"，不判断有没有真夹到（看到夹爪动作仍不等于检测到抓取成功）。

**滑杆**：四路舵机各一条，拖动后点「应用全部」，参数边界来自 `servo.limits`

### 3. 实时画面

画面不再是独立选项卡，就在这一页最下面，夹的时候一直能看到。

- **图像话题**：默认 `/image_raw`（原始画面）。下拉可切到算法调试图：
  - `/color_track_pick/image_result` 颜色抓取识别结果
  - `/line_following/image_result` 图像循线结果
  - `/object_tracking/image_result` 目标跟踪结果
  - `/llm_control/image_result` 大模型控制结果
- **自适应缩放**：窗口越小画面越小（只缩不放），不会把窗口撑变形
- **抓帧**：把当前帧存成 jpg/png，落在 `app/捕获/`，文件名带时间戳
- **开始录制**：录的是**你电脑上的文件**，不是车上的
  - JPEG 模式 → 存成 `.mjpg`，VLC / PotPlayer 可直接播放
  - PNG 模式 → 逐帧存到 `app/捕获/预览录像/帧序列_*/` 文件夹

## 五、怎么加一个新功能

以"加一个「里程计」选项卡"为例，三步：

**第 1 步**：新建 `carapp/features/odom.py`

```python
import tkinter as tk
from carapp.features.base import Feature
from carapp.ui import theme

class OdomFeature(Feature):
    key = "odom"
    title = "里程计"

    def build(self, parent):
        self.lbl = tk.Label(parent, text="--", bg=theme.BG, fg=theme.TEXT)
        self.lbl.pack(padx=12, pady=12, anchor="w")

    def on_tick(self, st):
        pose = st.get("pose")
        if pose:
            self.lbl.config(text="x=%.3f  y=%.3f  yaw=%.1f°" % pose)
```

**第 2 步**：在 `carapp/features/__init__.py` 里注册

```python
from carapp.features.odom import OdomFeature

FEATURES = [
    CameraFeature,
    GripperFeature,
    OdomFeature,      # ← 新增
]
```

**第 3 步**：重启程序。选项卡自动出现，`main.py` 不用改。

### AppContext 能给你什么

`self.ctx` 是所有公共能力的入口：

| 用法 | 作用 |
|---|---|
| `self.ctx.state` | 读全局状态（位姿、电压、节点数、帧率…） |
| `self.ctx.bridge.publish(topic, msg)` | 发布任意 ROS 话题 |
| `self.ctx.bridge.subscribe(topic, throttle_ms)` | 订阅任意话题（消息会进 `state`，需要自定义解析就在 `main.py` 的 `_on_ros_message` 加分支） |
| `self.ctx.bridge.call_service(srv, args, cb)` | 调 ROS 服务 |
| `self.ctx.publish_servo({"gripper":1500}, duration=0.8)` | 舵机指令的快捷方式 |
| `self.ctx.add_frame_listener(cb)` | 注册摄像头帧回调 `cb(ts, payload, mode)` |
| `self.ctx.save_dir()` | 拿到 `app/捕获/` 的绝对路径（自动创建） |
| `self.ctx.log("...")` | 往底部日志写一行 |

## 六、通信协议（排错时有用）

程序不碰 SSH，全部走车上已经跑着的两个服务：

| 端口 | 服务 | 用途 | 举例 |
|---|---|---|---|
| 8080 | `web_video_server` | 图像流 | `http://192.168.150.3:8080/stream?topic=/image_raw&type=mjpeg` |
| 9090 | `rosbridge_websocket` | 指令与状态 | `ws://192.168.150.3:9090` |

**控制夹爪实际发的消息**：

```json
{
  "op": "publish",
  "topic": "/ros_robot_controller/pwm_servo/set_state",
  "msg": {
    "duration": 0.8,
    "state": [{ "id": [4], "position": [1500], "offset": [0] }]
  }
}
```

**控制车轮实际发的消息**（车上的 `controller` 节点在订这条话题，和手柄/APP 同一条通路）：

```json
{
  "op": "publish",
  "topic": "/controller/cmd_vel",
  "msg": {
    "linear":  { "x": 0.06, "y": 0.0, "z": 0.0 },
    "angular": { "x": 0.0, "y": 0.0, "z": 0.0 }
  }
}
```

停车就是连发 3 次全 0（怕丢包，也怕控制器那边超时判定不一致）。
实测验证：发一条后，在车上 `ros2 topic echo /controller/cmd_vel` 能原样收到，说明话题名与消息结构都对。

**舵机 ID 对应关系**（改 `config/settings.json` 可调）：

| ID | 关节 | 范围 | 备注 |
|---|---|---|---|
| 1 | 云台俯仰 | 1150–2250 | 物理 1000–2400，两端各留 150；2 号车俯视 1300 / 前视 1500 |
| 2 | 云台水平 | 650–2350 | 物理 500–2500，两端各留 150 |
| 3 | 升降臂 | 1200–2000 | 1200 是硬件下限 |
| 4 | 夹爪 | 1500–2000 | 2000 张开 / 1500 闭合 / 1750 半开 |

## 七、常见问题

| 现象 | 原因与处理 |
|---|---|
| 顶部一直「● 未连接」，画面也黑 | 网线没插好 / 电脑 IP 不在 192.168.150 网段。先 `ping 192.168.150.3`，再点「自动搜索」 |
| 能 ping 通但连不上 | 车上 ROS 还没起来。开机后要等 40~60 秒；或服务挂了，需在车上 `sudo systemctl restart start_node.service` |
| 画面有但很卡 | PNG 模式带宽约 20 Mbps、JPEG 约 5 Mbps。装个 Pillow 就会自动切到 JPEG 模式（见下） |
| 夹爪点了没反应 | 看日志有没有「下发失败：ROS 未连接」；再确认 `/ros_robot_controller` 节点在（顶部节点数应为 33） |
| 双击 run.bat 一闪而过 | 没装 Python，或安装时没勾 "Add Python to PATH" |
| 中文变乱码 | 用 `run.bat` 启动（它已执行 `chcp 65001`），别用系统默认终端 |

**关于 Pillow（可选）**

装了会自动切换到 JPEG 模式：画质更好、带宽只有 1/4、帧率更高。不装也能用（PNG 模式）。

```bash
pip install Pillow
```

**双击 `run.bat` 后满屏「不是内部或外部命令」「乱码」**

这是批处理文件的**编码/换行**问题，不是程序问题。cmd 只认 GBK + CRLF 的 `.bat`；
如果被编辑器存成 UTF-8 或 LF 换行，就会出现 `'PYEXE' 不是内部或外部命令`、
`'"RUN=py -3"' 不是内部或外部命令` 这类错。

仓库里的 `run.bat` 已经是 GBK + CRLF，正常不会有这个现象。万一你用 VS Code
之类的编辑器改过它并保存，请按下图恢复：右下角编码选 **GB2312/GBK**，
换行符选 **CRLF**，或者直接重新拷贝一份原始文件。

（`run.sh` 只给 macOS/Linux 用，保持 UTF-8 + LF，两者不要混。）

**关于「夹爪看不到」**

2 号车本次画面能够看到夹爪。是否能看清取决于云台角度和车辆装配；程序尚未实现抓取成功检测，仍需人工观察或独立传感器确认。

## 八、移植到别的电脑要改什么

一般**什么都不用改**：

1. 整个 `app/` 文件夹拷过去
2. 装 Python 3.8+（勾 PATH）
3. 配好本机网段（`tools\设置本机网卡IP.bat`）
4. 双击 `run.bat`

只有两种情况需要动 `config/settings.json`：

- 小车 IP 不是 `192.168.150.3` → 改 `car.host`（或程序里点「自动搜索」）
- 有第二台车 → 改 `cars` 列表（见第一节第 5 小节）
- 小车不在 150 网段 → 改 `car.subnet_prefixes`（默认已含 `192.168.150` 与 `192.168.149` 两段），
  否则自动搜索扫错网段

## 九、已知限制

- 舵机**没有位置回读**：车上那个 `pwm_servo/get_state` 服务实现有 bug，一调就把控制器节点搞崩，
  所以顶部「夹爪目标」显示的是**最后下发的指令值**，不是实测角度
- 图像约 7~10 fps：相机配置写着 30 fps 但实际跑不到，瓶颈在 YUV 转换与 ROS 传输
- **没有里程计闭环**：车轮是"按时间推"的开环控制，走 0.6 秒约 3.6 cm 只是估算，
  地面打滑、电量、轮子摩擦都会让实际距离有偏差。要精确对位就用「点动 0.3s」一点点蹭，
  或者看画面自己按
- **未实现抓取成功检测**：2 号车可看到夹爪，但程序尚未自动判断是否夹住目标。
