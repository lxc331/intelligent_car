## 1. 项目是什么

两辆 ClawPi 智能小车（底盘/云台/夹爪/雷达）的 Windows 桌面控制台，Python + Tk，纯客户端，**电脑不需要装 ROS/OpenCV**：

- 控制走 rosbridge（`:9090`），视频走 web_video_server（`:8080`），终端/建图/网络配置走 SSH；
- 车辆档案：1 号车 `HW-10CCA58E`（有线 `.3`，热点 `192.168.149.1`），2 号车 `HW-A0857935`（有线 `.2`）；
- 入口：`app\run.bat`（Windows 双击）或项目根目录 `python -m carapp.main`（需在 `app/` 下或设 `PYTHONPATH`）。

已实现的功能页面（`app/carapp/features/`，在 `features/__init__.py` 的 `FEATURES` 列表注册）：

| 页面/功能 | 说明 |
|---|---|
| 夹取 + 实时画面 | 底盘点动、云台、四路滑杆、预设姿态、定时夹取、颜色追踪夹取 |
| 遥控 | 鼠标/键盘（WASD、QE 横移、IKJL 云台、TGFH 升降臂/夹爪、空格停止） |
| 自动巡航 | 迁移厂家 `lidar_controller` 三模式：避障 / 跟随 / 警卫（检测距离 0.30–1.50 m，速度 0.02–0.15 m/s） |
| 沙盘建模 | SSH 在车上跑 `slam_toolbox`，地图双端保存到 `app/savedMap/` |
| 沙盘导航 | Nav2 + AMCL：导入 YAML、标定位姿、点选目标、路径预览 |
| 集成终端 | SSH + pyte 终端，文件浏览（只读） |
| 两车连接 | 车辆档案、有线/AP/STA 切换、服务搜索、连接诊断、断线重连 |
| 红绿灯功能 | 本轮新增：新马线路口确认 → 场景减速 → 路口内红灯停车及恢复；YOLO26s 交通模型 + OpenVINO CPU 推理，顶部开关隔离，默认关闭 |

技术约定（详见根目录 `AGENTS.md` 与 README「开发与测试」）：

1. `/scan_raw` 实时数据走 `RealtimeRosDelivery`（ROS 接收线程更新），**不得经过 Tk 队列**；
2. 绘制/解码只在当前页 `on_tick()`，会话结果/录像收尾/许可检查在 `on_background_tick()`；
3. 新功能按职责放 `features/`、`core/`、`ui/`、`model/`，不往大文件里堆；改一个功能不影响其他功能；
4. 舵机/底盘动作走 `AppContext.publish_servo()/publish_twist()/stop_base()` 统一限位；跨页面运动占用查 `motion_in_use()` / `Feature.motion_active`。

- 修复：`make_clear()` 的帧时间改为 `(now-.95, now-.5, now-.05)`，留出间隙。**生产代码语义未改**（重复帧仍按设计拒绝）。
- 备份：`.work/backup_pre_fix/test_traffic_light.py`。

- 完整过程、命令、回滚方式：`.work/ACL清理记录_20261028.md`

## 9. 常用命令与坑


单进程 `python -m unittest discover -s tests -v` 在本机**当前环境下会中途崩溃**（约跑到 120 项后 `Tcl_AsyncDelete: async handler deleted by the wrong thread`，多个 Tk 测试共用解释器时的线程析构问题）。分模块跑稳定、结果等价，**以分模块结果为准**（533 项、2 跳过）。日志：`.work/test_modules_handover.log`；辅助脚本 `.work/run_tests_per_module.py`、`.work/run_full_suite.py`。

**注意的坑**

- Windows `time.monotonic()` 粒度 15.6 ms：涉及时间戳递增的测试/逻辑要留间隙（见 4.2）。
- 本机 DSH 沙箱下系统临时目录曾不可写，`tempfile` 相关测试报 `PermissionError`；用 `.work/sitecustomize.py` 打补丁，跑测试时 `PYTHONPATH` 要包含 `.work`：
  ```powershell
  $env:PYTHONPATH='D:\项目\intelligent_car-main\.work;D:\项目\intelligent_car-main\.work\pylib'
  ```
  （依赖已装系统 Python 后，一般不再需要 `.work\pylib`。）
- Tk 退出时的 `Tcl_AsyncDelete` / `main thread is not in main loop` 不影响测试结论，属已知噪声。

## 19. 2026-10-29 追加：斑马线像素行停车、里程计真相与低电压保护

### 19.1 用「斑马线像素行 + 里程计」停到停止线

- 实测（1 号车，前视 1500）：近处斑马线下沿像素行与离停止线距离线性相关
  `距离 ≈ 1.36125 − 0.002220 × 行号`（0.53 m→行 378、0.42 m→418、0.31 m→476）；
  行号到 `junction.row_trigger`（470，约 0.32 m）时切爬行，再按真实米数走满
  `junction.finish_travel`（0.22 m）锁停。**小于 0.3 m 时近处斑马线已出画面**，必须靠里程计收尾。
- 新增 `CrosswalkApproach`（`app/carapp/core/junction_drive.py`，纯逻辑不发布 Twist）：
  `step(row, red, travel, now)` → `DriveCommand`，阶段 IDLE / APPROACH / CRAWL / HOLD；
  参数校验「缺少路口接近参数」「斑马线行号斜率必须为负」「实际速度比例无效」等；
  `app/tests/test_junction_drive.py` 增加 12 例，与 `test_crosswalk_distance` 合计 37 例通过。

### 19.2 `/odom` 是指令积分，不是轮速反馈（重要）

- 车端 `odom_publisher_node.cal_odom_fun()` 用 `cmd_vel` 的 `linear_x * dt`、`angular_z * dt` 累加，
  不读编码器，**且完全忽略 `linear_y`** → 横移时 `/odom` 不动；它只能当"指令走了多少"。
- 实测真实速度约是指令的 **1.87 倍**（指令 0.06 m/s → 实际 0.112 m/s，用车前路障 + 雷达量得），
  代码用 `junction.speed_scale` 换算后再与 `finish_travel` 比较。
- 首次试验过冲 0.38 m 与"车走歪 20–30°"都源于此前的错误假设（把 odom 当真值、只发直行速度）。
- 麦轮 X 型：`mecanum.py` 里 `motor1 = vx - vy - wz*(wheelbase+track_width)/2`…，
  `wheelbase 0.1320 / track_width 0.1410 / wheel_diameter 0.059`；纯 `linear.x` 理论上直行，实际跑偏属机械/地面问题。

### 19.3 低电压保护

- 用户反馈：电压低于 **6.8 V** 触发报警（换车原因之一）。新增 `.work/battery.py`
  （`read_volts` / `ensure_ok`，`WARN_VOLTS=6.9`，话题 `/ros_robot_controller/battery`，>100 视为 mV），
  `.work/auto_stop.py` 在动轮前先读电压，未知或低于门限直接拒绝驱动。

### 19.4 换车后需要重做的标定

1. `speed_scale`（每台车可能不同，至少测 0.06 / 0.10 / 0.12 m/s 三个点）；
2. 斑马线行号映射（相机安装高度/角度变了就要重采 0.3–0.6 m 段）；
3. 云台三视角（俯仰方向、限位、抬头/低头值）。
